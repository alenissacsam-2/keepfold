# Keepfold tool and event schemas (frozen v1, 2026-11-13)

This file is the contract between the MCP server, the CLI and the skill. Change it only together with the code it describes.

**Guarded MCP contract (D7 §4.1).** `tests/test_mcp_contract.py` checks the served tools against `tests/fixtures/contract/mcp-1.json` (each tool's `inputSchema` and annotations for an owner, a reader and a `--private` server; the resource URIs; the `keepfold` prompt; the error codes below) and each tool's top-level result keys against `results-1.json`. The contract may only grow: a new tool, a new optional argument, a new enum value, a relaxed `required` or a new result key. A removed or renamed tool or argument, a type change, an optional argument made required, a dropped enum value or a changed default fails the test. Descriptions and `display` text are not frozen. The snapshots are rewritten only with `KEEPFOLD_WRITE_CONTRACT=1`, and this line must then name the new `mcp-1.json`'s sha256. The `mcp` SDK is pinned exactly, and every use of its internals lives in `keepfold/mcp_adapter.py`.

## Conventions
- **Names.** Tools are named `keepfold_*`, all arguments are snake_case, and dates are local ISO dates.
- **IDs:** `^[a-z0-9][a-z0-9.-]{0,80}$`. A concept, mistake or problem name may also be given as a title or alias. The server resolves it, and an unknown name returns `{"error":"unknown_concept","did_you_mean":[...]}`.
- **Access gate.** Every tool sees only what `keepfold.access` lets the viewer `mcp` see (`Keepfold._hidden` / `_sees`): a private domain, area or concept, everything under it, and their mistakes do not exist for the client. Such an id gets exactly the unknown-id result (`keepfold_ask`, `keepfold_grade`, including `item_id`s of asks on them, `keepfold_add` links; a `keepfold_log` self-report parks it in the inbox as it would an unknown name), is never in `did_you_mean`, and no card, open-mistake line or `keepfold_end` result names one.
- **Every successful result** is an object with at least `next` (one line telling the agent what to do next) and, where relevant, `display` (Markdown the agent must show verbatim).
- **Every error** is `{"error": <code>, "message": <one sentence that says how to fix it>}`. Codes: `no_session`, `read_only_mode`, `unknown_concept`, `unknown_id`, `invalid_id`, `duplicate_suggested`, `vault_locked`, `secret_detected`, `invalid_argument`, and `refused_exposed`, `role_refused` and `killed` (see "Roles, kill switch and access log"), and `refused` and `not_set_up` from `keepfold_browse_search`, and `restart_needed` (any tool; see "Stale server" below). Any tool that writes may also return `vault_too_new` (a newer Keepfold changed these notes: reads work, writes are refused until the user updates), `format_unreadable` (`.keepfold/format.json` cannot be read: reads work, the user runs `keepfold doctor`), `vault_upgrading` (retry in a minute) or `vault_needs_upgrade` (the user opens the Keepfold app). A call with an argument the tool's schema does not name runs nothing and returns `invalid_argument`, whose message names the unknown argument and lists the real ones (`keepfold_recall has no argument 'qurey'; its arguments are: query, …`).
- **Return caps.** The brief is ≤1.5k tokens, the contract ≤ 4,800 characters (≈ 1,200 tokens), `read` ≤1.2k tokens, `find` ≤8 hits. Note text read from the vault is wrapped in `<untrusted_note id="…">…</untrusted_note>`.
- **Idempotency.** Every write tool takes an optional `key`. A repeated key returns the first result and appends nothing. Keys live on events, so they survive a server restart. `keepfold_patch`, `keepfold_add` and the `keepfold_log` kinds that write files (`journal`, `capture`, `voice_sample`) store theirs on a `change` event `{note: "keyed", tool, id?, path?}`. A repeat of one of these from a later server writes nothing and returns `{duplicate: true, id?, path?, next}`, plus `recorded: 0` and `display_line` for a log, or `changed: false` and `summary` for a patch.
- **Sessions (always on).** Reads (`keepfold_prime`, `keepfold_context`, `keepfold_find` (kind `resurface` included), `keepfold_read`, `keepfold_reflect` (actions `pack` and `lint`), `keepfold_chats`, `keepfold_recall`, `keepfold_as_me`) work with no session and never open one, and so does `keepfold_log(kind=chat_turn)`, which writes the chat log outside the vault (`keepfold_prime` below). The first write (`ask`, `grade` (one item or an `items` batch), `log` (kind `void` included), `patch`, `add`, `reflect(action=split)`) with no open session opens one with mode `ambient`. It closes through `keepfold_end`, the 2 h idle close, the next `keepfold_start`, a full `keepfold_prime` (owner role, `related_only` false: a new chat, so each Chat conversation gets its own ambient session and `keepfold undo` is per chat; a study session is never closed this way), the server's own exit (stdin closed), or a sweep (server start, SessionEnd hook) once its server process is gone or it has idled 2 h; a session whose server is alive is never swept early. Only `keepfold_end` without a session returns `no_session`.
- **Merged actions (15 tools, plus `keepfold_browse_search` under `--private`).** `keepfold_find(kind=resurface)`, `keepfold_log(kind=void)`, `keepfold_grade(items=[…])` and `keepfold_reflect(action=lint|split)` replaced the tools `keepfold_resurface`, `keepfold_void`, `keepfold_quiz_result`, `keepfold_lint` and `keepfold_split` with the same arguments, checks and results; each action keeps the old tool's rights in the mode table and the role gate (`mcp_server._action`), and a refusal names the call as `keepfold_log(kind=void)`. No tool writes a dashboard: the brain and lists are the app's live home, which `keepfold dashboard` opens (it also rewrites `index.md`; no session close does), and an offline copy is the app's Export snapshot.
- **Server instructions.** The MCP `instructions` field (under 1,600 characters, tested) says first what Keepfold is for (any AI app knows the user without asking again, so read it first and save as you go), then tells every client to call `keepfold_prime` first in every new chat (with `related_only=true` if a hook primed it), `keepfold_context(topic)` once per later topic, to record everything automatically as it happens, without asking (the topic `touch`, concepts taught, graded answers, facts, sources, insights, decisions), and, about the user, to write their own words with `user_confirmed=true` and an inference without it (saved at once as a guess; ask only when it clashes with a line they gave). It also says every chat is logged in Keepfold (and to say so if asked), and, when `keepfold_prime` returned `chat`, to start each later turn with `keepfold_log(kind='chat_turn')`, unasked. `skills/keepfold/SKILL.md` says the same.
- **Tool annotations.** Every tool carries MCP `annotations` with `openWorldHint: false` (no Keepfold tool reaches outside the user's machine) and `readOnlyHint`: true for `keepfold_find`, `keepfold_recall`, `keepfold_read`, `keepfold_context`, `keepfold_chats` and `keepfold_browse_search` (they change nothing the user wrote; read and recall keep the local recall log), false for the rest.
- **Stable text.** What a client keeps in its prompt prefix (these instructions, the tool descriptions with B2-c's core lines, the rules-file block, the skill) holds no date, count or recent item, so it stays byte-identical until the owner's own lines change (an `(until …)` line dropping off on its day aside), and the client's prompt cache keeps working.

## Tools

### keepfold_start
| Arg | Type | Notes |
|---|---|---|
| mode | enum home, learn, review, log, short, about, week, capture, reflect, project, save, history, sweep, mock (capture to history: all write tools, no quiz plan, start card shows a one-line hint; sweep: `today` is up to 10 concepts for one cold quiz, `planner.sweep`; mock: all write tools, empty `today`, the card keeps coming assessments and open mistakes (no plan line), `brief` starts with `MOCK_BRIEF` (about 1,000 characters: modes/mock.md's rubric and `mock-<stamp>-<phase>` key scheme, for a mock the model starts where the plugin skill cannot load), `next` points at `modes/mock.md`; the server instructions and this tool's description let a chat start it when the user asks for a mock interview) | default home. `home` returns only `session`, `display` (a short map card), `contract` (core rules, no domain overrides), `preferences` (as keepfold_context scope all: personality + preferences) and `next`; no `brief`, no `today`. `home` also returns `unlearned`: the count of listable past chats (Claude Code, and Claude Chat once imported) with no `chat_learned` event (each transcript read only up to its second user turn; the chat being written is left out); when > 0 the card's **Waiting for you** shows `N past chats to learn from`, and `next` says to offer saving this chat first if it already had a conversation, then read up to 5 of them (`unlearned=true`, `who="user"`, ≤ 2 parts each), propose about-me lines (never `user_confirmed`), log `chat_learned` per chat, and ask about all waiting about-me lines at once (cards of up to 4, or a numbered list) |
| topic | string? | the learn/short focus (a concept, area or domain name) |
| model | string? | self-reported model name, stored in `grader.model` |
| minutes | int? | learn, short, review: cut `today` to a session this long (1-240; `planner.fit`): items in plan order while their estimated minutes (`planner.MINUTES`, estimates) fit, the tail dropped, never reordered; a first item longer than the budget is kept alone; the card adds `**Time:** about 28 of 30 min (estimate)`. mock with topic `paper`: one of 15, 30, 45 (default `planner.PAPER_MINUTES`, 45) and the result adds `paper` (below). Any other mode, or a bad value, is `invalid_argument`. Without it, nothing changes |

- **Behaviour.** If a session is open in this process, it is closed first with the full end pipeline. Then a new session opens.
- **Returns** `{session, mode, display, brief, contract, today, next}`:
  - `contract` is `me/teaching-contract.md` with `## Domain overrides` scoped to the topic and today's top 5, cut at 4,800 characters (≈1,200 tokens) with `[truncated]`; when cut, `next` says to run `keepfold doctor` (which warns over the same size);
  - `today` holds `[{kind: unchecked|asked|confident_miss|warmup|track|refresh|new, id, title, state, why, subject}]`: unchecked, asked, confident misses and warm-ups first, then refreshes and plan steps (`track`) grouped by `subject` (a catalog domain id, or a plan's track id when it has none): a named topic's subject first, then the most recently studied subject (its latest grade, ask, taught or evidence log, or a touch naming it); ties and each subject's refreshes keep the risk order; then new. When a due refresh concept builds on (`requires`, transitively, nearest first) a concept that is due, Needs refresh or Learning and not already listed or private, that ancestor leads the refresh block with `why` "<ancestor> first: <concept> builds on it" (at most one a plan, inside the cap; the concept stays listed). A plan (a track note) has no dates: its steps are its unchecked checklist items in the note's order (one per linked id; headings, `## Day N` included, and `current_day` are ignored), and `why` is the plan's title. Each plan gives its next 3 steps, then, if more are left, one pointer `{kind: track, id: null, title: "More steps are in <track>", why: <track title>, more: <track id>}`: not a task, never graded. A track's subject is its `subject` field (a domain, area or concept), else the domain most of its links fall in. Nothing is "behind": switching subjects only moves the other plans down. A track's `deadline` (else an old `placement_date`) is a real date: the card's and Today.md's **Coming up** list it beside the assessments as "<plan title>: N days left" (`planner.deadlines`, kind `deadline`; the dashboard's `assessments` too). `unchecked` is newest taught first and drops a concept whose latest `taught` is more than 7 days old (its state is unchanged); in `short` mode the 5 items are confident misses first, then concepts tested by an assessment within 2 days, then this order, one item per concept.
- **Mock paper.** `keepfold_start(mode="mock", topic="paper", minutes?)` adds `paper`: `[{kind: paper, id, title, state, why, anchor, minutes}]` from `planner.mock_paper`: the soonest pending non-private assessment's tested concepts (else every concept with evidence), ranked by weight x (1 - recall now, + 1 with an open mistake), fitted to `minutes` (an item with a problem `anchor` is 15, else 5), domains interleaved as in sweep; private and hidden concepts never appear. `anchor` is a non-private problem (unsolved first, each once), else a resource covering the concept, else null. The card adds `**Practice paper:** N questions, about M of 45 min (estimate)`; `next` points at the Paper section of `modes/mock.md`.
- **Week.** `keepfold_start(mode="week")` returns `week` (`planner.week_summary`) plus `week.confidence`: `learning_eval.confidence_mirror` over all graded answers on non-hidden concepts, `[{confidence 1-4, label, n, right, share}]` with right = correct at hints ≤ 1 and `share` null under `MIN_BAND` (10). When any answer carried a confidence, the card adds the lines "When you said 4 (certain), you were right 9 of 12 times" (or "not enough answers yet (n)"). Display-only: nothing in scheduling or FSRS reads it.
- **Stale server.** When a `keepfold` package `.py` file on disk (subpackages included) is newer (by more than 1 s) than the code this server loaded, every tool call returns `{"error": "restart_needed", "message": "Keepfold was updated after this server started; restart Claude to load the new tools.", "next": "Tell the user to restart Claude; nothing was recorded."}` and runs nothing, since an editable install would mix old in-memory modules with new lazily imported ones. The scan runs at most once every 5 s; a tool that raises `ImportError`, `AttributeError` or `NameError` while the code on disk changed returns the same error instead of crashing.

### keepfold_context
| Arg | Type | Notes |
|---|---|---|
| scope | enum all, coding, communication, learning, projects, environment, career, personal | default all |
| topic | string? | natural-language topic; concepts come from recall hits (full-text without the model) |

Read-only; needs no session. **Returns** `{context, searched?, next}` (`searched` as in `keepfold_recall`, when a `topic` found nothing or only weak matches; `next` then leads with the same not-found line). `context` is Markdown of at most 2,400 characters (about 600 tokens):
- **Profile:** the `summary:` of `me/profile.md`, else its first paragraph; the `keepfold init` template summary "Who I am" is replaced by the live list lines of its non-reserved sections; a served claim line carries its label as below (review B3: ` (ask)` for a line of tier agent or exposed), with the legend;
- **Topic** (with `topic`): up to 3 concepts with state glyph, next due date, the gap-check note when it applies, and open mistakes: the first concept hits of the Related recall when the model is downloaded, else a full-text match on all words, retried on any non-stopword word when that finds nothing;
- **Related** (with `topic`): up to 5 pages of any kind (not private): `keepfold_recall(topic, 5)` when the model is downloaded, else full-text hits plus one graph hop around the top three; each `- [[id]] — summary or title`, wrapped as `<untrusted_note id="related">`; whole lines are dropped to fit the cap; left out when nothing clears recall's cosine floor;
- **Active projects** (scope all or projects): title and summary of each `status: active` project;
- **Personality** (≤ 400 characters): the non-empty `## Communication` (scope all, communication) and `## How I think` (scope all, learning) sections of `me/personality.md`;
- **Goals** (scope all, ≤ 200 characters): the `## Now` section of `me/goals.md`;
- **Preferences:** the `## <Scope>` section of `me/preferences.md` (every section for `all`; `## Workflow` counts as `coding`);
- **Setup** (scope all, environment): the sections of `me/setup.md` (hardware and software).

In these three blocks (and the home `preferences`), each section's list lines come after any other lines; `## Past` and `## Not me` and empty sections are never served, and `^c-…` claim ids are stripped. **Labels and ranking:** each live claim line gets a suffix from its tier (`claims.tiers`): ` (ask)` for tier agent or exposed, or a relayed yes from `claims.RELAYED_FROM` (keepfold_patch below); else none: the user's own lines (typed, legacy, confirmed) are served plain. List lines are ordered by score = 0.5, × 0.3 for `(ask)` lines (`prime.served_claims`), ties newest first, so a cap trims the weakest. A copied line with its ` (ask)` suffix (or an old ` (said)`) still resolves as a claim (`claims.resolve`). When any served line is ` (ask)`, a server-written block `## How to read the claims` comes before Personality (not wrapped): `(ask) = check with the user before relying on it.` **R3-3: one line of a waiting pair.** While a recorded pair (an `update_of` or `supersedes` pair, keepfold_patch below) waits unresolved in the app's Review with both lines live on non-private pages, its older line is left out of `keepfold_prime`, the prime hook and `keepfold_context` (Core, Profile, Preferences, Personality, Goals) as if muted in the X-ray (`prime.held`, derived from the events at read time; nothing is stored or deleted). Once the user keeps both or one, serving follows that.

Note text is wrapped in `<untrusted_note>`. A missing profile reads "not recorded yet; ask the user and save it with keepfold_patch."; missing preferences say so only in the home `preferences` (`keepfold_start`), never in `keepfold_context` or `keepfold_prime`.

### keepfold_prime
| Arg | Type | Notes |
|---|---|---|
| prompt | string | the user's message; only its first 2,000 characters are used; blank is `invalid_argument` |
| related_only | bool = false | true in a chat the hook already primed: `context` holds only the Playbooks, Lately, Related, Open mistakes and Coverage blocks (no Profile, Preferences or contract); `touch` and `next` as usual |

**Core in the tool list (B2-c).** For the owner role (not a reader or an excluded folder), each `tools/list` answer appends to `keepfold_prime`'s description "The user's standing preferences, from their Keepfold notes:" (a label, never an order to the model) and the pinned core lines `packs.rule_block` writes into that MCP client's rules file (its profile's scopes), whole lines within 700 characters; nothing for Claude Code (`claude-code`, whose hook primes every chat) or with no pinned line, and no `list_changed` notification is sent, so an app sees a changed core at its next list.

**Changed outside Keepfold (R5a) and other apps' guesses (R5d).** On `me/core`, `me/setup` and `me/teaching-contract`, a non-blank line (a heading too; on the contract, front matter too; not `## Past` or `## Not me`) is served only when it was on the page at the baseline, or Keepfold wrote or approved it. The baseline is `<vault>/.keepfold/guard-baseline.json` (`{"lines": {page: [hash]}}`), taken once, from the pages as they are, by the first owner-role `keepfold_prime` or the app's tidy pass after the upgrade; a hash is sha256 of the line without its claim id, whitespace collapsed, markers kept, first 16 hex characters. Each `keepfold_patch` change on these pages records the hashes of the lines it wrote (`lines`), and the app's **Keep** logs a `dismiss` change on id `outside` with the hash. Any other line (an edited one counts as new) is left out of prime's Core, Teaching contract and Preferences, `keepfold_context`, the rules files and the `tools/list` core until kept; a removed line needs nothing. An inferred line (tier agent or exposed, served (ask)) whose session's `open` event names a client reaches only that client; a line with no recorded client is served as before, and a caller with no client name gets no line another app recorded.

The first call of every chat. Needs no session, though a full prime first closes an open ambient session (Sessions above); it writes nothing to the vault but one ids-only Agent X-ray row (below; never a recall-log row). **Chat log.** In a Claude app whose chats Keepfold has no transcript of (the client names itself with `claude` but not `claude-code`: the Desktop Chat tab) and only for the owner role, prime also starts that chat's log: it appends the prompt (redacted with `chats.redact`) as a `user` line, server-stamped, to `<export root>/claude-live/<chat>.jsonl` (`~/.keepfold/claude-chat/claude-live/`, outside the vault), where `<chat>` is a new ULID the server makes, and returns it as `chat`; `next` then asks for `keepfold_log(kind="chat_turn")` at the start of each later turn. A full prime starts a new chat; `related_only=true` keeps the current one (the chat touched last, within 2 h). The automatic chat import turns the log into a chat page (`keepfold_chats` below). Claude Code and the Desktop Code tab are saved from their own transcripts, so there prime logs nothing and returns no `chat`. **Returns** `{context, touch, chat?, tags?, next}`; `tags` (one line per tag acted on) when the prompt held a `//pref:`, `//fact:` or `//forget:` line (//tags below), and then `next` says not to save them again. `context` is Markdown of at most 2,000 characters (about 500 tokens), the owner's standing text first and the prompt's and the week's after it, in this order:
- **Core** (≤ 500 of line text, `CORE_MAX`): the pinned lines of `me/core.md` (a claim page: `- ` lines under any `## ` section but `## Past` and `## Not me`), verbatim without claim ids, in page order, always and first. Only lines the user wrote or confirmed count (the tiers served plain: typed, legacy, confirmed; never agent, exposed or relayed (ask) lines); a line that does not fit is left out whole, never cut. Wrapped as `<untrusted_note id="me/core">`. No page, a private page or one withheld from this role: no block. The core is never shrunk; its size comes out of the Preferences cap, and the parts after it get what is left of the 2,000;
- **Profile** (≤ 250): as in `keepfold_context`, left out when not recorded;
- **Teaching contract (core)** (≤ 400): the start of `me/teaching-contract.md` without domain overrides;
- **How to read the claims:** as in `keepfold_context`, when any served line is labelled;
- **Preferences** (≤ 800, minus the Core): every list line of `me/preferences.md` and `me/setup.md` (all sections) and of `## Communication` and `## How I think` in `me/personality.md` not already in the Core, each as `- [<Section>] <line>` with the claim labels of `keepfold_context`. When the server process already has the embedding model loaded (its warm-up), they are ordered by cosine between the prompt (with the bge query prefix) and `<Section>: <line>` times the tier weight (1, or 0.3 for an (ask) line), a cosine under `MIN_COS` counting as no match; line vectors are cached in memory by text, so each line is embedded once per process. Prime never loads a model: otherwise (the prime hook, no model, not warm yet) they are ordered by how many of the prompt's words (3+ letters, not stopwords or task words, plus the long forms of study abbreviations such as dbms → database, `prime.ABBREVIATIONS`) the line contains. Ties go to the general sections (Communication, Working with AI, Learning, How I think), then the served score; whole lines are dropped from the end to fit; wrapped as `<untrusted_note id="me">`; none: no block;
- **Attempt first** (ideas-r2 #2): when the prompt names a `todo` or `attempted` problem note (its `lc-<n>` id, LeetCode URL slug or a 2+ word title), one plain line asking once for the user's approach and grading it with `keepfold_grade`; its size comes out of the Preferences cap, so the budget stays the same;
- **Playbooks** (G4; also with `related_only`; out of the Related 450, at most 337 of it, and Lately gets at most what is left): up to 2 `note` pages tagged `playbook` that the prompt matches, as `- [[id]] title: summary` (summary one line, ≤ 60 characters) in `<untrusted_note id="playbooks">`, then the plain line `Follow it for this task (keepfold_read it first); if the user corrects how, keepfold_patch that playbook.` A playbook matches when it is a non-linked hit of the recall below, or its title or summary holds a content word of the prompt (the Preferences terms: 3+ letters, no stopword or `prime.TASK_WORDS`, plus `prime.ABBREVIATIONS`); hits come first, then the most shared words. Candidates are read from the index, so never a private or hidden page; an X-ray-muted one is out, and one with `scope: <access.SCOPES>` reaches only a client whose profile has that scope or `all` (no `scope`, or `all`: every client). A playbook whose last write Keepfold logged (`keepfold_add`, or a `keepfold_patch`, which records a `tier` for note pages as for claims) was an agent's and whose file has not changed since (2 s slack) is not served at all (R5b: an AI app follows a playbook's steps, so "(ask)" is not enough); the owner's own edit of the file, an app click, or a `keepfold_patch` with `user_confirmed=true` from a clean chat lets it through. One whose title, summary or body fails `claims.unsafe` (an order to an AI, a chat template token, invisible characters) is never served while Keepfold logged its last write. A page shown here is not repeated in Related or Lately; the X-ray records `playbooks` (served and trimmed);
- **Lately (recent, use only if relevant)** (RR-21; out of the Related 450, which shrinks by this block's size; at most half of it): up to 3 pages (projects too) that a `change` event or a `touch` log named in the last 7 local days, newest first, as `- [[id]] — title` in `<untrusted_note id="lately">`; never a private, hidden or withheld page (only indexed pages, as Related), an X-ray-muted one, an imported chat page, the touched hub or a Related candidate; the X-ray row records them as `lately`;
- **Related** (≤ 450): the top 3 non-hub hits (hubs as in `keepfold topics`, so the root `my-topic-map` too) of `keepfold_recall(prompt, 8)` (with the reranker when present; keyword + graph without the model), as `- [[id]] — summary or title`;
- **Open mistakes** (≤ 250): at most 2 open mistakes (the fold's `open_mistakes`, as in `keepfold_context`) of the non-linked concept hits among those 8, skipping private and hidden notes, as `- [[id]] — summary or title`, wrapped as `<untrusted_note id="mistakes">`; none: no block;
- **Coverage** (RR-5; last, its room kept before Related, so it is never crowded out; also with `related_only`): one line of the sources the index holds, wrapped as `<untrusted_note id="coverage">`, then the plain line `No result means not recorded, not that it never happened.` A source is an import's `Source:` label (`Git`, `Notes`, `Highlights`…), `<app> chats` for imported chats, `browsing`, `journal`, or `notes` for the user's own notes, resources, decisions, projects and loops; each with its first and last month (`2024-02 to 2026-11`, from page dates only), most pages first, at most 6 then `+N more sources`. Only what MCP can see counts: the index holds no private page and no private browsing, and leaves out what a client's profile withholds. Absent when the vault has none of these pages.

A block that lost whole lines to its cap (Preferences, Teaching contract (core), Related, Open mistakes) ends, after its `</untrusted_note>` and inside the same cap, with `(+N more <preference|contract|related|mistake> lines: <call> reads them)`, the call being `keepfold_context(scope='all')`, `keepfold_read(id='me/teaching-contract')`, `keepfold_recall(query=<the message>)` or `keepfold_context(topic=<the topic>)` (`prime.fit`, `prime.more`).

`touch` lists at most one topic hub (a note tagged `topic`, as in `keepfold topics`), and only when two views agree (`topics.prompt_hub`): `attach` of the prompt's bare vector (no query prefix) to the hub member centroids (floor `TOUCH_FLOOR` 0.71, margin 0.02 with LCA back-off, never the root) and recall, where a hit that is not a graph neighbour must be that hub, under it, or filed at or under it. Unsure, ambiguous, no hits or no embedding model: an empty list. A hub this session already logged is left out. `next` says to record them with `keepfold_log(kind="touch")` once if the message is substantive, and to record everything else durable at once, unasked: the user's own words about themselves with `user_confirmed=true`, an inference without it (saved at once as a guess).

**Hook (Claude Code plugin).** `plugin/hooks/hooks.json` runs `keepfold prime-hook` on `UserPromptSubmit`. It reads the hook JSON on stdin (`session_id`, `prompt`; vault from `~/.keepfold/config.yaml`; `KEEPFOLD_VAULT` only when it names that vault or none is configured, so a project cannot point the hook at its own folder). On the first prompt of a `session_id` it records the id in `<vault>/.keepfold/primed` (last 200, before priming, so a slow or failing prime is never retried; read and written under the vault lock with a 1 s wait, so two chats opened together both stay marked, and skipped when the lock stays busy) and prints `{"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": "<a line saying the chat is primed, then context, then next>"}}`. The context is only the light part of `keepfold_prime` (`keepfold.prime.core`: Core, Profile, contract core, claims legend, Preferences (word-overlap order: the hook never loads the model), Attempt first; same caps, wrapping and text as the server's), built from the vault and the event log without the `mcp` SDK, the embedder or the index, so it takes about 1 s from a cold process on a 5,200-note vault. Its `next` asks the model, when the message is substantive, to call `keepfold_prime(prompt=<message>, related_only=true)` on the running server for the Related block and `touch`, then log the touch as that result says. The light prime runs in a thread with a 3 s safety budget (`BUDGET`); when it is not done in time (or fails) `additionalContext` is instead a nudge to call `keepfold_prime` before answering, and the process exits at once without waiting for the thread. A miss never affects later chats. Every prompt, the first and later ones, is also scanned for //tags (below), saved as the owner's own words (the `mcp` SDK is imported only when one is new) and named in one added line (`TAGGED`). **Later prompts (G3, G5).** A later prompt of a primed chat that is not a greeting, an ack or a slash command runs the same light prime for the new prompt (same budget; skipped silently past it) and prints only its Profile and Preferences claim lines whose `^c-…` ids this chat was not served yet and that share a word with the prompt, at most 400 characters wrapped as `<untrusted_note id="me">`, after a one-line header (`keepfold.delta.HEAD`), recorded in the X-ray like the first prime. Every 8th prompt of the chat (8, 16, …) it adds the same save sentence as `chat_turn` (below). The served ids and a prompt count per chat live in `<vault>/.keepfold/primed-served.json` (`{"<session id>": {"n": <prompts>, "ids": ["^c-…"]}}`, newest last, the last 200 chats, written through the vault under its lock); the first prime records what it served there, so a delta never repeats it. A corrupt sidecar makes later prompts behave as before (and the next new chat starts it over). Later prompts with nothing new and no tag, a session in an excluded folder (`exclude:`, under Roles), bad input or any error print nothing. It always exits 0 and runs without loading the CLI. The Chat tab has no hooks, so there the server instructions and the skill ask for the `keepfold_prime` call.

**Re-served after compaction (RR-6).** The same command also runs on `SessionStart` with matcher `compact|resume|clear`: when the payload's `source` is one of those, it prints `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "<a line saying why it is served again, then context, then next>"}}`, the light prime built for an empty prompt (Core, Profile, contract core, Preferences in their general order; same caps and 3 s budget; a nudge to call `keepfold_prime` on a timeout), whose `next` asks for `keepfold_prime(prompt=<next message>, related_only=true)`. It does not touch `.keepfold/primed`. On `PreCompact` it prints one plain line: `Keepfold: record durable items now (keepfold_patch / keepfold_log) before context is compacted.` Both print nothing in an excluded folder, without a vault or on bad input, and exit 0.

**Agent X-ray (`keepfold.xray`).** Every `keepfold_prime`, `keepfold_context` and prime hook appends one row to `<vault>/.keepfold/xray.jsonl` (git-ignored, the last 500 calls, never an event): `{ts, tool, client, served: {block: [ids]}, trimmed: {block: [ids]}, chars}`, where `client` is the MCP client's name (`claude-code` for the hook) and a block is `core`, `profile`, `preferences`, `contract`, `related`, `mistakes`, `playbooks`, `hub` (prime) or `profile`, `topic`, `related`, `claims` (context). Ids only: a page is its bare id (`me/profile` for a me/ page), a claim is `^c-…`; `trimmed` lists what the character budget cut. No prompt and no text. The write is best effort (a 0.2 s lock wait, errors swallowed). The owner's **Pin** and **Mute** live in `<vault>/.keepfold/xray.json` (`{"pin": [ids], "mute": [ids]}`), set only by clicks in the Keepfold app's Agent X-ray (`/api/xray/pin`, `/api/xray/mute`); no MCP tool takes them. A pinned page is listed first in prime's Related (unless it is private or hidden, or a hub), and a pinned claim leads its Preferences, both still within the caps. A muted page or claim is never served by prime or context (Related, Open mistakes, the hub, Topic, Core and claim lines).

### keepfold_find
| Arg | Type | Notes |
|---|---|---|
| query | string | full-text search over title, aliases, headings, body; each word a prefix term, all required. A `"quoted span"` is an exact phrase and a leading `-word` leaves that word out (`index.fts_query(syntax=True)`; no stemming); a query with only exclusions, or one FTS5 refuses, falls back to the plain words |
| kind | enum concept, area, domain, mistake, problem, assessment, application, resource, note, project, decision, journal, loop, due, ready, weak, resurface, timeline? | `due`, `ready` and `weak` ignore `query` if it is empty; `resurface` ignores it (see kind `resurface` below); `timeline` takes a page id or words (see kind `timeline` below); `due` is the planner's due set (Needs refresh, or `next_due` today or earlier) |
| limit | int 1–8 (1–12 for `timeline`) | default 8; 3 for `resurface`; 12 for `timeline` |
| since | YYYY-MM-DD? | only pages dated on or after it (RR-31; ignored by `resurface`): a page's `date`, its `Date:` line or a day in its id, else for a note or resource the day its file last changed (Chat's `ask._note_day` rule); an undated page never passes; a malformed or impossible day, or `since` after `until`, is `invalid_argument` |
| until | YYYY-MM-DD? | only pages dated on or before it, as `since` |
| source | string? | only pages whose import `Source:` line (near the top) names this label, any case: `Git`, `Notes`, `Obsidian`, `Highlights`, `Calendar`, `ChatGPT`…; `mine` keeps the pages no import wrote; blank is `invalid_argument` |
| where | string? | frontmatter filters (FW, `keepfold.where`): up to 6 clauses `field op value` separated by spaces, no spaces around the operator, a value with spaces in double quotes; every clause must pass. Operators `=`, `!=`, `<`, `<=`, `>`, `>=`, `~` (contains). Keys and strings compare in any case, stripped; a `[[id]]` or `[[id\|label]]` value on either side compares as the bare id. A list field passes `=`, `~` and the orderings when any element passes and `!=` when none equals. Two days (`YYYY-MM-DD`; a timestamp by its first 10 characters) or two numbers compare as such under every operator but `~` (`rating=4` matches 4.0, `date=2026-11-20` a timestamp that day); otherwise `=` and `!=` compare as strings and `<` `<=` `>` `>=` fail; a bool compares to `true`/`false`. A missing field fails every operator but `!=`; an unknown field is no error. Applied with `since`/`until`/`source`, before the limit. A blank `where`, an unknown operator, a clause without one or without a value, an unbalanced quote or more than 6 clauses is `invalid_argument`; kinds `resurface` and `timeline` refuse it. Example: `where='tags=dsa due<=2026-12-01 title~"binary search"'` |

With `where` and no query, find lists the pages that pass (of `kind` when given; loops, problems and `due`/`ready`/`weak` keep their own order), newest first by the `since` day rule (undated last, then by id), up to `limit`.

**Returns** `{hits:[{id, kind, state, glyph}], text, searched?, next}` (a loop hit is `{id, kind}`; `searched` when nothing was found, as under `keepfold_recall`). `text` holds the note text, one line per hit, best first, wrapped as `<untrusted_note id="find">`: `- [[id]] title (status, loop_type, due D)? — summary?`, then the snippet (≤ 120) indented on the next line. `summary` is the note's `summary:` property, when it has one; the loop part only for loops. Ids, kinds and states stay outside the wrapper.

### keepfold_recall
| Arg | Type | Notes |
|---|---|---|
| query | string | natural language: "what do I know/think about X" |
| limit | int 1–20 | default 8 |
| hops | int 0–2 | default 1; graph hops around the seeds |
| check | bool | default false; the Honest Double, below |
| chats | bool | default false; true searches imported chat pages at full weight |
| since | YYYY-MM-DD? | only pages dated on or after it (RR-31; picked from the best 20 hits, so a match ranked past them is missed): a page's `date`, its `Date:` line or a day in its id, else for a note or resource the day its file last changed (Chat's `ask._note_day` rule); an undated page never passes; a malformed or impossible day, or `since` after `until`, is `invalid_argument` |
| until | YYYY-MM-DD? | only pages dated on or before it, as `since` |
| source | string? | only pages whose import `Source:` line (near the top) names this label, any case: `Git`, `Notes`, `Obsidian`, `Highlights`, `Calendar`, `ChatGPT`…; `mine` keeps the pages no import wrote; blank is `invalid_argument` |

Read-only; needs no session. Score = 0.7 × cosine (local `BAAI/bge-small-en-v1.5` embeddings; a page is embedded as chunks and its cosine is its best chunk's: chunk 0 is title + summary + the first 1,500 body characters, the others are the title plus windows of about 1,000 characters over the rest of the body, overlapping by 200 and cut at a turn (`### `, `**Me:**`) or paragraph boundary; the query alone gets bge's "Represent this sentence for searching relevant passages: " prefix) + 0.3 × BM25 over the FTS index (any word except ~40 English stopwords, scaled so the best hit is 1). A cosine under `MIN_COS` (0.62; with the query prefix unrelated pages score about 0.45-0.56, real matches 0.7 and up; raised from 0.6 for chunks so the same share of pages clears it per query as head-only vectors did at 0.6) counts as 0. With the model, a page under the floor is a hit only when its keyword match covers at least half of the query's non-stopword words (`MIN_KW_COVER`), so "best pizza in naples" does not return pages that merely say "best", while an exact id or title such as "LC 1293" still matches; without the model every keyword match counts. An unrelated query returns no hits. An imported chat page (a resource whose `Timeline:` line has `Source: <app>`) scores × 0.6 (`CHAT_WEIGHT`) after these floors, unless `chats` is true, so the user's own pages rank first while a chat that is the only match still returns; `keepfold_prime` and `keepfold_context` get the same weighting. **Harvest quieting** (`harvest.quiet`, passed as `quiet` by `keepfold_recall`, `keepfold_prime`, `keepfold_context` and `keepfold recall`): a chat in a live `harvested` event weighs 0.4 instead of 0.6, after the same floors; a copy folded under its keeper weighs 0 and leaves the hits and the graph neighbours, even with `chats=true`, which lifts harvested chats to full weight. The top hits are seeds; their graph neighbours (edges both ways, private pages skipped; edges are frontmatter link fields plus `mentions` for body `[[links]]` of every kind, outside code fences and not already a frontmatter edge) score seed × 0.5 per hop and fill up to a quarter of `limit`. **Returns** `{hits:[{id, kind, score, match: similar|keyword|linked, via?, at?, passage?}], text, notice?, searched?, next}`: `text` lists `- [[id]] title — summary` per hit, best first, wrapped as `<untrusted_note id="recall">`, with ` (from outside text)` after the title of a page whose latest `change` event was written in an exposed session; `via` (linked hits) is `<from id> (<edge type>)`. **Evidence (RR-12).** The top 3 hits (not with `check=true`) also carry `at`, the offset in the page body where their best passage starts (the best chunk's start, else the first line holding a query word, else the body's start; at a line start, so `keepfold_read(id, at=…)` reads around it), and `passage`, that text on one line, at most 300 characters (`semantic.PASSAGE`), wrapped as `<untrusted_note id="<id>">`. A passage from a page whose `keepfold_read` exposes the session (an imported chat, a browse page, a resource or note with a URL or `raw/` source) exposes it too. Without the model, hits are keyword + graph only and `notice` is "semantic search not set up; run `keepfold model download`"; a tool call never downloads anything. Vectors live in `<vault>/.keepfold/vectors.db` (a disposable cache, SQLite in WAL mode: one row per page with its id → (path, mtime_ns, size) manifest, whether all its chunks are built, its chunk start offsets and float16 vectors; its meta records the model, text version 3 and the chunk settings, and any change empties it; an older `vectors-v3.npz` is read in once and never written again, and `semantic.prune` deletes it once it holds a row of a page that went or changed; a damaged store is moved aside as `vectors.db.damaged-<UTC stamp>` (`keepfold.quarantine`, `PRAGMA quick_check` at a process's first open) and started again). A save upserts or deletes only the pages that changed; each process loads the rows into one matrix on its first query and then reads only the rows other processes saved since (a change stamp in the meta). Each call drops deleted pages, spends at most 1 s (`HEAD_BUDGET`) embedding chunk 0 of new and changed pages, then at most 1 s (`RECALL_BUDGET`) on missing further chunks; a page with no chunk 0 yet scores by keyword only, and a page whose chunks are not all built scores by those it has. So a deleted cache or a large import never embeds the whole vault inside one call; later calls or `keepfold model build` fill the rest. Saves merge in what another process saved meanwhile, so a server and a build never undo each other. `raw/` and private pages are never embedded. CLI: `keepfold recall "<query>" [--limit --hops --explain --show-misses]` (`--explain` prints each hit's raw best-chunk cosine, scaled BM25, keyword cover, weight, rerank score and best chunk; `--show-misses` the next 5 pages that missed the cut and why; the CLI never writes recall-log rows), `keepfold model download` (fetches the model once into `~/.keepfold/models`, then builds the configured vault's vectors; `--voice` instead installs faster-whisper and fetches the speech model for voice memos, the only path that does), `keepfold model build` (builds every chunk without downloading, about 45 min for 5,000 pages, saving each minute; rerun to resume), `keepfold model status`.

**Rerank.** When the cross-encoder `Xenova/ms-marco-MiniLM-L-6-v2` is in `~/.keepfold/models` (fetched only by `keepfold model download`), the top 30 hits of the scoring above (seeds and linked pages) are reordered by it over each hit's best chunk (the chunk that gave its cosine; chunk 0 for a hit without one), then cut to `limit` (a chat page's sigmoid of the cross-encoder logit is × 0.6 unless `chats`); `keepfold_context(topic)` does the same for its Related list. Rerank changes only the order: each hit's `score` and `match` keep the meaning above. The Honest Double check never reranks. Absent, failing to load, or `rerank: false` in `~/.keepfold/config.yaml`: the order above, silently.

**What was searched (RR-14).** An empty or weak result never reads as "no record exists". `keepfold_recall` (weak: with the model, no hit is a `similar` match, only keyword or linked ones), `keepfold_find` (empty only; not kind `loop` or `resurface`) and `keepfold_context(topic)` then add `searched: {pages, kinds, by, excluded, ranked_lower?}`: `pages` the pages that search could see (of its kinds, after `since`/`until`/`source`), `kinds` a list or `"all"`, `by` `keyword + meaning` or `keyword` (`keepfold_find`, or no model), `excluded` what never takes part (`private pages`, `private browsing`, and `pages this app's profile withholds` for a profiled client or a reader), `ranked_lower` (recall and context without `chats`) that imported chats rank lower. `next` says `Not found in the N pages searched (by): not recorded in Keepfold is not the same as never happened.` (or `Only weak matches in …, so check them before relying on them: …`), then what to try.

**Usage log.** Each `keepfold_recall` (not `check=true`) and `keepfold_context(topic)` appends `{ts, rid, tool, query, ids}` to `<vault>/.keepfold/recall-log.jsonl` (gitignored, last 5,000 rows, not an event); a `keepfold_read` within 10 minutes in the same server process appends `{ts, opened: rid, id}`, linked to the latest such recall that returned the id, else the latest one. `keepfold eval recall [--k 8]` replays each recall whose returned ids were opened (relevant = every id opened after it) through the variants `current`, `rrf` (reciprocal rank fusion of the cosine and keyword lists, k = 60), `rerank`, `rrf+rerank` and `no-downrank` (`current` with `chats=True`, no `CHAT_WEIGHT` down-rank of imported chat pages), and prints recall@k and MRR per variant and the query count (under 10 it says the set is too small to trust).

**Learning calibration.** `keepfold eval learning [--since DAY] [--json]` is read-only (no file, event or commit). Each graded primary item the fold sees (voids and remaps applied; asks excluded) is paired with the `predicted_p` on its own event; pass = correct at hints ≤ 1 (the fold's rule). Items with no stamp (CLI and imported grades, `problem_status`, older self_reports) are counted as skipped. It prints n, base rate, Brier, the Brier of a constant base-rate forecast and the skill score (1 − Brier / base Brier), log loss, the reliability gap (n-weighted |forecast − pass| over 5 bins of 0.2), a secondary Brier with partial = 0.5 (`levels._score`), the bins, the same numbers split by `mode` (`ambient`, `study` = home/learn/short/review/log/reflect/sweep, else the mode (so `mock`) or `none`), grader (the server makes an `answer_key` match correct and otherwise keeps the model's verdict, so for a tutor grade whose ask had a key: `key-agrees` = matched, or not matched and graded wrong; `key-disagrees` = not matched yet graded correct or partial; `model` = a tutor grade with no key; else the `source`: `external`, `self`, `imported`), `source`, `item_type` (none = recall), confidence given or not, `first` (`cold` = the first graded item on the concept that local day with nothing on it earlier that day, plus its ≤ 2 s batch, as the fold rates a day; `later same day` = after feedback or teaching; the headline is also printed for cold only) and `prior` (`first review` = no earlier graded item or `also` credit on the concept, the 0.5 default; `history`), and the `model_verdict -> verdict` disagreement pairs with counts. Once any `spot_check` log exists it also prints how many model verdicts the user kept (`spot_check{n, agree, rate}` in `--json`). Rows under 30 pairs say "too few". Code: `src/keepfold/learning_eval.py`.

**Harvest status.** `keepfold harvest status [--since DAY] [--json]` (`keepfold eval harvest` is a hidden alias) is read-only (it may only fill the vector cache): chats and harvested; placement coverage (chats whose home hub has a concept at cosine ≥ 0.68, harvested share; needs the model) and how many of those hubs are bridged; bridged hubs (a hub with an index edge to a concept page); the yes-rate (live `me/` claim lines citing `[[chat-` against `## Not me` ones); waiting about-me lines; the 7-day keep share (pages named by `harvested` events 7+ days old that still exist); the empty rate per app; and each run (session) with its bundles, chats, pages and `keepfold undo <session>`. `--since` limits the event-based numbers.

**Eval history.** `keepfold eval [--k 8]` (or `keepfold eval all`) runs the recall eval and the learning Brier, prints one table and appends one row per metric to `<vault>/.keepfold/eval-history.jsonl` (gitignored; no event or commit): `{date, git_sha, index, metric, variant, value, n, baseline_value}`, numbers only, never a query or page text. `metric` is `recall@k` and `mrr@k` per recall variant (baseline `current`; the rerank variants only with the reranker downloaded) and `brier` (variant `all`, baseline the constant base-rate Brier); a signal with n = 0 writes nothing. `git_sha` is the code's commit (`-dirty` with uncommitted changes), `index` a hash of the indexed pages' path, mtime and size plus whether vectors were used. The "vs base" column is value − baseline; the paired column is value − the latest earlier row with the same date, index, metric, variant and n from another `git_sha`. Rows from another day or index never pair, because replaying old queries on a grown index moves the numbers with no code change. Code: `src/keepfold/eval_history.py`.

**Honest Double (`check=true`).** For text written as the user (a CV, an application, an email, a reply). The query is split into sentences (at `.`, `!`, `?` and line breaks; leading `-`/`*` bullets dropped); more than 20 sentences or 4,000 characters is `invalid_argument`. Each sentence is recalled on its own (same scoring and floors, no hops) and its top hit of kind `concept` that is a semantic match (`match: similar`) with score ≥ 0.5 is checked, so keyword-only or weak hits never flag; private pages are not in the index, and sentences with no concept hit are left out. The result adds `checks:[{sentence, concept, title, state, verdict, applied?}]`, with `verdict`: `ok` (state `solid`, or the concept is in the `applies` of a non-private project with status `active` or `shipped`; then `applied: true`), else `hedge` (`learning`, `needs_refresh`), else `unverified`. `next` is the rule: do not assert beyond Solid, hedge Learning, drop or rephrase unverified claims, and show the user each flag with its concept. Advisory only; it never blocks.

### keepfold_read
| Arg | Type | Notes |
|---|---|---|
| id | string | a note id, `raw/<path>` for a source under `raw/`, or `people/<slug>` for a people page |
| sections | string[]? | headings to include; default is all, up to the cap |
| at | int or string? | where to start (RR-12): an offset in the page body (a recall hit's `at`, or a read's `next_at`; moved back to its line start when that is under 200 characters back, so a very long line still pages on) or a heading's text (with or without `#`s, any case); an unknown heading is `invalid_argument`; not with `sections` |
| window | int? | characters to read from `at` (200 to the cap; ends at a line end in its second half when it can); a non-number is `invalid_argument`; not with `sections` |

**Returns** `{id, kind, title, state, fields:"<untrusted_note…>", text:"<untrusted_note…>", neighbours:{parent, requires[], required_by[], mistakes[], problems[]}, recent:[≤5 events], open_mistakes[], next_refresh, next_at?, similar?[{id, title}], next}`. A read cut short (by `window` or the cap) ends its `text`, inside the wrapper, with `[truncated: N more characters; the rest's headings:]` and up to 8 heading lines of the rest (`(+N more headings)` past them), returns `next_at` (the offset the rest starts at, a line start) and its `next` says `keepfold_read(id='<id>', at=<next_at>)` reads the next part, or `at=<a listed heading>` jumps there; a `sections` read cut by the cap still ends with a bare `[truncated]`. The `Summary:` line leads only a read without `at`. `title` sits outside the wrapper, so it is plain text (`render.plain`, 120 chars: no links, images, URLs or tags). `similar` (RR-23; left out when empty): up to 3 meaning-neighbours, pages whose head (chunk 0) vector has cosine ≥ `semantic.MIN_COS` with this page's, highest first, never the page itself, a page linked to it either way, or a private, hidden or withheld page; titles plain as `title`. Only vectors the server already holds in memory (a recall built them) are used: this path never loads or downloads the embedder, so a cold server omits it. A note with a `summary:` property starts its `text` with `Summary: …`. `fields` is the frontmatter (no `keepfold_*` keys) as one `<untrusted_note id="<id>">` block of `key: value` lines (strings as is, lists and other values as JSON); `""` when there are none.

`raw/<path>` returns `{id, kind:"raw", title, size, text, next}`: the text of a `.md` or `.txt` file, capped like a note and wrapped in `<untrusted_note>`; other file types return metadata with `text: null`. Paths that resolve outside `raw/` fail with `invalid_id`; the source of a private resource fails with `unknown_id`, like a missing file.

Privacy: a note with `private: true`, and every catalog entry under a private domain or area (the views' `planner.hidden` rule), is absent from `keepfold_find`, `keepfold_read`, `keepfold_recall`, `keepfold_context` and the vector cache.

`people/<slug>` returns `{id, kind:"person", title, fields:"<untrusted_note id=\"people/<slug>\">relation: …\ntier: …", text:"<untrusted_note id=\"people/<slug>\">…", next}`. People pages are private unless their frontmatter says `private: false` (`vault.is_private` is true for every other `person` note), so private ones are absent from search, recall, the dashboard, `index.md`, lint and reflect; only this exact id (or `keepfold_as_me`) reads them, and `next` says to use the page for this task only. A page with `private: false` is also indexed under its bare slug, and `next` says to cite it. A bare slug of a private page or an unknown id fails with `unknown_id`. Session notes say "changed a people page" and never name the person.

| key | string? | with `items`, each item is keyed `<key>:<n>` |
| items | [{question, answer, verdict or correct:bool, confidence?, concept?, item_type?, item_id?, hints?, mistakes?}]? | a finished quiz at once, 1–20 items; only `concept` (the default concept for items) and `key` may go with it, any other single-item field is `invalid_argument` |

**Returns** `{state_before, state_after, display_line, mistake?, similar_mistakes?, next}`. With `similar_mistakes`, `next` suggests merging via `keepfold_patch` if they are the same mistake. When only the 7-day gap check keeps the concept from Solid, `display_line` ends with ` · one more check after a break (from YYYY-MM-DD)`; a batch's per-concept display lines and `keepfold_context`'s topic lines carry the same suffix.

With `items` the whole batch is validated before anything is written, each item gets its own `predicted_p` from the log as it stood before the batch, and it **returns** `{recorded, per_concept:[{id, state_before, state_after}], display, next}`. The first batch in a session with no item carrying `confidence` gets `Next time, collect how sure (1-4) per question.` appended to `next` (never refused).

Its claude-code ids set `learned` in `keepfold_chats` list and leave the home `unlearned` count; voiding one undoes that.

Appends a `log` event `{kind: reconfirm, claim: <resolved id>, verdict}`. `no` only records the answer (retire the line with `keepfold_patch`). v6 U3: a `yes` logged in a `reflect` session (user-started) that is not exposed gets a server-stamped `promote: true`, and `claims.tiers` then counts an `agent` or `exposed` line, or a relayed yes from `claims.RELAYED_FROM`, as `confirmed` with `confirm: reflected`. - **touch:** `{ids: [1-5 page ids]}`, usually `keepfold_prime`'s `touch`: the chat was about these pages (topic hubs). An id that is not an indexed (non-private) page is `unknown_id`. Each page is logged at most once per session (the server keeps a per-session set; a new session starts empty), so ids already logged are dropped and a call with none left writes nothing and returns `{recorded: 0, display_line: "Already recorded in this chat", next}`. Otherwise appends one `log` event `{kind: touch, ids: [the new ids]}` (no object, so levels and the planner ignore it). In the Chat tab one server serves every chat, so "per session" can span chats until the session closes (2 h idle).
- **harvested** (harvest verdict item 3): `{chats: [1-80 imported chat page ids], dupes?: {copy: keeper}, pages?: [≤ 50 ids], found?: int 0-50, outcome?: harvested|empty}` after one `keepfold_chats(action="harvest")` bundle, with `key` = its `bundle`; or `{outcome: skipped, hub: <topic hub or area id>}`, which drops that subtree from the queue; the hub may be a private one on disk (its `log.md` line then says `skipped a private hub`). Every chat must be an indexed `is_chat` page; a dupes pair must both be in `chats`, from the same day and app. Chats already harvested are dropped; a call with none left is `already_harvested`, and a key already in the log writes nothing and returns `{recorded: 0, display_line: "Already recorded", next}`. Otherwise appends one `log` event `{kind: harvested, outcome, chats, dupes, pages, found}` (or `{kind, outcome, hub}`) and `## [day] harvest | N chats → M pages` to `log.md`; no journal line. A void (or `keepfold undo` of the session) puts the chats back in the queue.

**Voice zone (`voice.py`).** `voice/` is no kind folder, so the index, `keepfold_find`, `keepfold_recall`, vectors, the dashboard, `index.md` and lint never see it, and `keepfold_context` never serves it; it is committed like the rest of the vault. An old vault's `voice/drafts.jsonl` (drafts, since removed) is left as it is; only `keepfold forget` still reads it. CLI: `keepfold voice import <file> --audience X --act Y --channel Z` adds the messages of a file separated by `---` lines (all or none; CRLF read as LF); `keepfold voice` prints sample counts per audience and channel.

**Unknown concepts** (`taught`, `self_report`, `felt_weak`, `problem_status` concepts, an assessment's `fields.concepts`) go through `safety_net.Linker`, the safety net's own rule: a catalog id, title, alias or slug; else (embedder already in memory only, never loaded or downloaded) a concept page at cosine ≥ 0.85; else the catalog's near-duplicate "did you mean"; else a new concept, made like `keepfold_add`, under the area most concepts this session touched or logged share, else the area most concepts under the name's (+ summary's) `topics.attach` hub share, else `From chats › Unsorted`, linked `related` to that hub. For taught and self_report the display line then starts "Created <title> under <domain> › <area>." and the result adds `id`; the session's Changed list shows the add. A junk, generic or secret-looking name (`safety_net.clean_name`, 2+ letters), a name matching a hidden concept (`planner.hidden`), and any unknown name in review mode is recorded as `inbox:<slug>` and added to `inbox.md` instead.

**Returns** `{recorded, display_line, next}`.

**Claims.** The claim pages are `me/personality`, `me/preferences`, `me/goals`, `me/profile`, `me/voice`, `me/core` and `me/setup` (`claims.PAGES`; a line added to `me/setup` waits for Approve like one for `me/preferences`); a claim is one `- ` line under a `## ` section. `## Past` and `## Not me` are reserved: they hold no live claims and are never served.
- **Ids.** Every `- ` line appended to a claim page gets a server-written Obsidian block id at its end, ` ^c-xxxxx` (5 chars of `[a-z2-7]`: base32 of sha256(`me/<page>` + `\n` + normalised text + `\n` + day), the next 5 on a clash on the page; normalised = no id, no `(confirmed …)`/`(proposed …)`/`(rejected …)`/`(until …)` markers, collapsed whitespace, lowercase). One bare line is written as a list line; an id in the caller's text is dropped. A line with no id is read with a derived id (the same hash with day `""`), written onto it only when an op moves it.
- **revise** (`target` id, `text` new wording): the line moves to `## Past` with ` (until YYYY-MM-DD → ^c-new)` and keeps its id; the new line takes its place with a new id. On `me/personality` and `me/preferences` it needs `user_confirmed=true` (else `invalid_argument`) and gets ` (confirmed YYYY-MM-DD)`.
- **retire** (`target` id): the line moves to `## Past` with ` (until YYYY-MM-DD)` (`until`, default today; revise uses it too). `## Past` is created at the end of the page if missing. An id that is not a live claim is `invalid_argument`.

A later unconfirmed `append_to_section` whose normalised text matches a `## Not me` line is not saved: `{changed:false, queued:false, summary, next}`.

G-Q9-15: a page `keepfold_add` writes as its own file (every kind but a catalog entry, a fleeting note and a person) in an exposed session carries `exposed: true` in its front matter (server-stamped, never a tool field), so a later tidy or consolidation can tell summarized outside text from the owner's own words; nothing reads the field yet. With `user_confirmed=true` it also carries `change.confirm` (idea 11): `clicked` when the user ticked yes in the consent dialog or clicked in the Keepfold app's Review (plan 5a; never a late relay), else `relayed`; `claims.tiers` gives each live `confirmed` row a `confirm`, `relayed` for an event without one (every yes before the dialog), `reflected` for a reflect `reconfirm` promotion (act-grade, like `clicked`), `tagged` for a line written from a //tag the owner typed (act-grade too). **Hook taint (NEXT.md item 2):** the Claude Code plugin's `PostToolUse` hook runs `keepfold taint` after WebFetch, WebSearch and every `mcp__` tool except Keepfold's own (`mcp__keepfold__`, `mcp__plugin_keepfold_keepfold__`) and servers that return no outside text: the desktop app's built-ins (the one-word `ccd_*` servers, not `ccd_session_mgmt`, which returns other chats' text; `visualize`, `scheduled-tasks`) and `savvy-progress` (Desktop Commander, Windows-MCP, browsers and connectors still count); it reads the hook JSON on stdin and atomically writes `<vault>/.keepfold/taint` (`{ts, tool_name, session_id}`; vault from `~/.keepfold/config.yaml`; `KEEPFOLD_VAULT` only when it names that vault or none is configured, so a project cannot point the hook at its own folder), always exits 0 and prints nothing. Before each tool call the server stats that marker: one newer than the server's start and under 2 h old exposes the session like a Keepfold outside read (so `refused_exposed` and the `exposed` tier apply). Known limit: the marker is per vault, so a web read in any concurrent Claude Code chat exposes this server's session too (the safe direction). The Chat tab and Claude Desktop have no hooks, so there only Keepfold's own outside reads expose. A live line no event wrote is `legacy` if the `claims_baseline` holds its id, else `typed` (hand-written). ### keepfold_end
| Arg | Type | Notes |
|---|---|---|
| summary | string ≤600 | |

**Behaviour.** It always closes the session. It rewrites the `keepfold_status` and `keepfold_next` properties of the touched concepts, writes the session note, the journal and `log.md` lines and `Today.md`, and commits the files this session wrote. A **quiet** session (no changes, asks, grades, patches or adds, and only ledger logs: `touch`, `resurfaced`, `access`, `chat_learned`) skips the note, journal, `log.md` and `Today.md` and commits only its event file. No close rebuilds `index.md` (`keepfold dashboard` does). Other uncommitted changes go first in their own `keepfold: other changes before session <id>` commit. Before committing, each changed file under 1 MB is checked against the secret patterns; a file that matches stays uncommitted and is listed in `not_committed` as `<path>: <pattern>` (never the key itself). `display` and the session note list every `keepfold_patch`/`keepfold_add` of the session under **Changed** (repeats as ×N, 15 lines max); no section when nothing changed. When the session created notes (`kind: note`, fleeting ones included), `display` adds `**New notes this session:** N (<count> <note_type>, …)`, types sorted, `untyped` for a note without one. The session note, `display`, `unchecked` and the close result never name a private or hidden concept (`planner.hidden`) or a changed page that is private: they are left out, and the note's Concepts list ends with one line, "N private topic(s) not listed."; the events, levels and tool properties still cover them.

Write budget: the write that first takes the session past 10 patches + adds, or past 40 asks + grades + logs, appends a one-time "This session has made N changes" or "has recorded N events; consider wrapping up with keepfold_end." to its `next`. It never blocks. Mistakes minted by `keepfold_grade` are listed as `- added mistake <id>`.

**Returns** `{display, counts:{asked, graded, logged, patched, added}, unchecked[], commit, next:"session closed"}`. `unchecked` (and the start card's "Taught, not yet checked") follow the planner lane's rule (`planner.fresh_unchecked`): newest taught first, nothing taught more than 7 days ago.

Close also regenerates `index.md` (non-private notes by kind, concepts domain > area with state glyphs) and appends `## [YYYY-MM-DD] session | <mode>, N changes` to `log.md`.

### Obsidian graph links and `keepfold relink` (CLI only)
New pages carry the links Obsidian's graph needs: a session note gets `Up: [[YYYY-MM-DD]]` under its H1 (its start day, else end day, when that journal page exists); a new journal page starts with `Up: [[YYYY-MM-01]]` (its month page, if it exists) or, for a month page, `Up: [[my-topic-map]]` (if `notes/my-topic-map.md` exists). Adding or forgetting a person rewrites the generated hub `notes/people.md` (structure note; `- [[people/<slug>]]` per public page, private pages left out, as in `index.md`), puts `People: [[people]]` under the H1 of `me/profile.md` (not a claim line) and `Up: [[people]]` on each people page. Frontmatter edges use the `"[[id]]"` form `keepfold_add` already writes. `keepfold relink [--dry-run]` applies all of this to existing pages through the vault (idempotent), converts plain frontmatter edge ids (`related: ["x"]`; not `domain` or `tests`) to `"[[x]]"` when note x exists, and reports every unresolved `[[target]]` (Obsidian resolution: path or file name, any case; code spans and fences ignored) with count and example: `near` (a note id after case, slug or folder fixes: rewritten), `junk` (not slug-like, a single word or a number: escaped to `\[\[...]]` in the body; left in frontmatter) or `missing` (slug-like: listed, never created). It prints orphans before and predicted after, by top folder. It also joins each public study domain page (`domains/`) to the public topic hub(s) it matches and prints each pair: a normalised name of the domain (id, title or alias; lowercase, `-`/`_`/spaces unified, `&` → `and`) must equal a whole hub name (title, alias, or a trailing run of its id's segments after `topic-` that has at least two segments or one of 5+ characters, so `system-design` ↔ `topic-software-system-design` but never `os` ↔ `topic-…-cosmos` or `data` ↔ `topic-…-data`); of a matched hub and its matched sub-hubs only the most general is kept, shortest id first, at most three per domain. The domain gets `- [[hub]]` under `## Topics`; the hub gets `- [[domain]]` under `## Study domains`, placed before the sections `keepfold topics build` regenerates, so rebuilds keep it. Both are idempotent.

### Topic tree and `keepfold topics` (CLI only)
The tree is read from the vault. A hub is a `kind: note` page with `topic` in `tags`; its parent is the first `related` id that is also a hub (cycles broken at the first repeat); the root is `my-topic-map`. A resource's or note's topics are the hub ids in its `related`, mirrored by its `Topics:` line (frontmatter wins). Private pages are never members, never listed on a hub and never edited.
- `keepfold topics status`: counts only: hubs per depth, hubs over 25 direct pages, resources and notes, unfiled ones.
- `keepfold topics attach [--dry-run] [--margin 0.02] [--floor 0.80] [--limit N]`: files every unfiled non-private resource and note that is not a hub by the rule under keepfold_add (one hub each), printing `attached A of N (area a, subtopic b, leaf c); left unfiled U` (depth 1, 2, 3+) and up to 10 (or N) lines `page -> hub (score): page title -> hub title`. `--limit N` tries a seeded sample of N unfiled pages. Needs the embedder; writes as `set_topics` does.
- `keepfold topics build [--dry-run]`: regenerates in place only the generated parts of each hub: the `Part of …` line under the H1 (`Part of [[my-topic-map]].` on an area, `Part of [[parent|title]] · first explored … · last … · <source> <n>, …` below), `## Sub-topics` (`## Subtopics` on an area, `## Areas` on the root) and `## Conversations` (`## Other conversations` when it has sub-topics; `- <date> · <source> · [[page|title]]` by date), plus each month page's `## Links` (topics that month rolled up to depth 2, projects its digest lines name). Date and source come from a page's `date` or its `Timeline: … · Source: … · Date: …` line; `## Watched & searched` lines count as activity. What I know, What I explored, What I'm curious about, How it grew, Start here, Watched & searched, `summary` and any hand text are never rewritten: a page whose other text would change is skipped and reported. Prints hubs and month pages changed and unchanged. A dry run writes nothing, not even the lock file.
- `keepfold topics eval [--margins 0.01,0.02,0.03] [--floor 0.80]`: read-only leave-one-out over the pages that have hubs (the page's vector is removed from its own hubs' centroids): attached share, precision (the hub is one of the page's or an ancestor of one), exact share and attachments by depth per margin. Needs the embedder.
- `keepfold topics eval --splits`: read-only, over the hand-split hubs (children holding pages, at least 10 pages counting the parent's own): the manual split's mean cosine silhouette (p25, the `SIL_MIN` candidate, and median), the median browse-cost reduction (a page costs the child list plus its child's list, or the parent's leftover list, against the flat n) manual against automatic and their ratio (gate ≥ 0.80), median cohesion (mean pairwise cosine within a child) and the median ARI of the automatic split against the manual one. Needs the embedder.
- `keepfold topics split [HUB] [--propose | --apply --auto-names]`: with no HUB, lists the split candidates as `hub (n pages)`: hubs with more than 25 direct pages at depth < 4, biggest first, then parents of children still marked `names: provisional`. `--propose` writes and prints the hub's proposal (see split proposals below). `--apply --auto-names` applies it offline, naming each child from its c-TF-IDF terms ("Bfs Dfs Graph") with `names: provisional` in its frontmatter; this is for users with no chat. Needs the embedder.

**Split proposals** (`topics.propose_split`, read-only on the vault): the input is the chunk-0 unit vectors of the hub's direct, non-private pages. For each k in 3..min(8, n // 4), spherical k-means (numpy, k-means++ starts, seeded, 10 restarts of 30 iterations, best total cosine kept); the k with the best mean cosine silhouette wins. A cluster with over 45% of the pages gets one k+1 retry, kept when it fixes that and still clears `SIL_MIN`; otherwise the proposal carries a `note`. Pages with a negative silhouette, and clusters under 4 pages, stay on the parent (`stay`). No proposal when the best silhouette is under `SIL_MIN` (0.06: the p25 of `eval --splits` on the real vault), fewer than 2 clusters remain, fewer than 12 pages, or the hub is at depth ≥ 4. Each cluster has `members`, `terms` (top 3 c-TF-IDF title words: tf × log(1 + mean cluster words / the word's count over all clusters), no stopwords or digits) and `sample_titles` (the 5 nearest its centroid). `hash` is the first 16 hex of sha256 over the hub, the sorted member ids, k and the seed. Written to `.keepfold/proposals/split-<hub>.json` as `{hub, hash, k, silhouette, clusters, stay, note?}`.

The CLI `keepfold reflect` prints a short version.

#### action `lint`
Read-only, needs no session. **Returns** `{findings:[{kind, id, detail}], totals:{kind: n}, next}`: at most 30 findings, sorted by severity (`id_clash`, `sync_conflict`, `missing_link`, `merged_related`, `orphan`, `no_summary`, `weak_summary`, `links_no_reason`, `resource_no_covers`, `stale_project`, `long_note`, `old_fleeting`, `unlinked_mention`; vault order within a kind), with at most 10 `unlinked_mention` and 10 `weak_summary`. `totals` counts every finding before the cut, and `next` names what was not shown ("140 more unlinked_mention"). Kinds: `id_clash`, `sync_conflict` (a sync tool's conflict copy, Syncthing, OneDrive or Dropbox, anywhere in the vault but dot folders and `browse/private/`; its id is the copy's vault path, its detail names the original; copies of private pages are not reported), `missing_link`, `orphan` (no links in or out; `me/` and session notes excluded), `resource_no_covers`, `stale_project` (active, file not modified in 30 days), `long_note` (permanent, over 350 words), `no_summary` (permanent, empty `summary`), `weak_summary` (RR-26, any kind but `me/`, session, browse and rollup pages: a set `summary` under 30 characters, or whose words and the title's overlap by more than 0.7, Jaccard without stopwords), `links_no_reason` (permanent, `## Links` missing or empty, or a bullet that is only `[[x]]` with no reason), `merged_related`, `unlinked_mention` (a public concept title of 2+ words in a note body, whole word, any case, with no link to it), `old_fleeting` (unchecked `inbox.md` line `(fleeting, <date>)` older than 7 days). Private notes are never reported. The CLI `keepfold lint` prints the same list, then `N findings (not shown: …)`, and appends `lint | N findings` to `log.md`. `keepfold lint --findability` (RR-26, report only, never edits) then checks every non-private page with a second chunk (`semantic._chunks`): the first 20 words of that chunk (its header line left out), as a recall query with no reranker and no graph hops (imported chats unweighted), must put the page in the top 3; keyword + vector with the downloaded model, keyword only without it (it never downloads). Each miss prints as `not_findable: <id> - '<words>' from its second chunk does not find it in the top 3`, then `N pages not findable by their own text`.

### keepfold_log kind `chat_saved`
`payload {source: claude-code|claude-chat|chatgpt|gemini|perplexity|claude-live, chat_id, title, pages[] (≤ 50 ids, default []), again?}`, after saving a chat in `save` or `history` mode. `chat_id` is the `keepfold_chats` id for Claude Code, or whatever id the Chat app's past-chat tool gives. The dedupe ledger: appends a `log` event with `payload.kind = chat_saved` (no object, so levels ignore it), `## [day] chat | <title> (N pages)` to `log.md` and `Saved chat: <title> (N pages)` to today's journal. A second save of the same `(source, chat_id)` returns `already_saved` unless `again: true`; voiding the event lifts the block.

The automatic chat import (`chat_import.py`: the app every 5 minutes, `keepfold import-chats --auto`) reads every source `keepfold_chats` lists: Claude Code transcripts (the CLI and the Desktop Code tab write the same files), Desktop Cowork transcripts, imported exports and the live Chat-tab logs (pages titled `Source: Claude`). It writes its own `chat_saved` events (session `import`, source `imported`, key `chat-import:<sha1 of source:chat_id, 16 hex>:<hash>`): `payload {kind: chat_saved, source, chat_id, title, pages [id], auto: true, hash, category?}`; `category` is the sensitive category that made the page private (the app's **Chats kept private** list, GET `/api/browse/private-chats`; no MCP tool reads it). Here `hash` is the first 16 hex of the sha256 of the page body without its `Topics:` line. The import rewrites a page only while its body still has the latest `hash`, so a page you edited is left alone. It never brings back a deleted page, never touches a chat that has a `chat_saved` event without `auto` (saved by hand), and writes no `log.md` or journal line per chat (one `chat | N chats saved automatically` line per pass). The home feed skips `auto` events. Chat pages from an earlier import that match a chat (same app, same first message, within a day) are adopted in the import's state, with no event. A live Chat-tab log and a claude.ai export conversation are one chat when their first user messages match (redacted, whitespace-normalised, first 200 characters), their first user turns are at most 15 minutes apart, and neither has another such candidate. They share one page (the one either already has; two existing pages stay apart, and so does a hand-saved partner), holding the export's turns plus the live user turns after the export's last message that follow the last live turn the export holds. Each write records a `chat_saved` event for both `(source, chat_id)` keys. R3-6: under the `Timeline:` line a page starts with a fact header: `When: <day>` (or `<first day> to <last day>`), `Who: me and <app>` and, for a coding session, `Where: <project link or name>`; an existing page gets it the next time its transcript changes (the body-hash rule above makes that an in-place rewrite).

### keepfold_find kind `resurface`

### keepfold_find kind `timeline`
R26: what else the owner was doing around one page's day. `query` is the anchor: a page id (resolved as `keepfold_read` resolves it), else the top hit of a plain `keepfold_find` for those words (any kind); only a page this client may see counts (a private, withheld or out-of-scope page's id answers exactly as no match); none is `{hits: [], text: "", next}` with a `next` that says to pass a page id from a find. The window is the anchor's day ±3 days, the day `since`/`until` filter by (a page's `date`, its `Date:` line or a day in its id, else for a note or resource its file's last change); `since` and `until` each replace their own bound (`since` alone: `until` is the later of the anchor's day + 3 and `since` + 6; `until` alone: `since` is the earlier of the anchor's day − 3 and `until` − 6), `source` filters as above, and an undated anchor needs both `since` and `until`. It lists the journal, note, resource, decision, project, loop and concept pages dated in the window, plus the anchor whatever its kind; only index pages, so exactly what `keepfold_find` serves this client (no private or browse-private page, none the app's profile withholds, nothing for an app no profile names); events with no page never appear. At most 12 (`limit` caps it), the ones nearest the anchor's day kept, then oldest first. **Returns** `{hits:[{id, kind, day, anchor?}], text, next}`: `text` is one line per page, `- DAY · kind · [[id]] · title`, the anchor's line starting `▸` instead of `-`, wrapped as `<untrusted_note id="find">`. Read-only, needs no session; no `searched`.

### Roles, kill switch and access log
- **Roles.** `keepfold mcp --role owner|reader` (default owner, today's behaviour) fixes the role for the server's life. `keepfold mcp --private` (needs `browse.private_mcp: true`) adds `keepfold_browse_search`, for local models only. `reader` may use only the reads listed under Sessions except `keepfold_chats` and `keepfold_read` of `people/…`; every other tool (`keepfold_start`, `keepfold_end` and every write) returns `{error: "role_refused", message, next}` with `next` naming the role. The gate runs before the tool, so a refusal writes nothing. `keepfold_reflect(action="pack")` is owner-only too (it is the owner's review of claims, portrait and `inbox.md` about-me lines; `action="lint"` stays a read).
- **Share tiers bind every non-owner read.** A `reader` server serves only the `me/` pages `share.allowed(vault, "work")` admits (`share: work` or `public`; missing means `self`): `Keepfold._withheld()` lists the others, and they are left out everywhere: the index treats them as hidden (so `keepfold_find`, `keepfold_recall`, `keepfold_read` (`unknown_id`), and the Related blocks of `keepfold_prime` / `keepfold_context` never see them, and the snapshot skips them), `keepfold_prime` / `keepfold_context` drop their Profile, Preferences, Personality, Goals and teaching-contract text, and `keepfold_as_me` subtracts them from the audience's pages. A block left empty says `withheld: N me/ page(s) not shared with this server's role.` The owner role is unchanged.
- **Start-up.** Only an owner server runs the orphan-session sweep and the catalog sync in `build_server`; a reader writes nothing to tracked vault files when it starts (the derived, git-ignored `.keepfold/` snapshot, vector cache and recall log may still be written, without the withheld pages). A reader never opens a session.
- **Excluded folders.** `exclude:` in `~/.keepfold/config.yaml` lists folders (a client's repo, cloned code) where Claude Code gets no Keepfold profile and no writes. A folder matches when the session's folder is it or under it, by whole path components after resolving (case-insensitive on Windows). The session's folders are the hook payload's `cwd` (`keepfold prime-hook`) or the process's working directory (`keepfold mcp`), plus `CLAUDE_PROJECT_DIR` when set. There `keepfold prime-hook` prints nothing (and marks nothing), and `keepfold mcp` refuses every tool, reads included, whatever `--role` says (its server instructions are one line saying Keepfold is off there), printing a note on stderr; its refusals are `role_refused` with a message naming the excluded folder and `next` pointing at `keepfold exclude remove`. CLI: `keepfold exclude add <path>` (a folder already covered is left alone), `keepfold exclude list`, `keepfold exclude remove <path>`; they rewrite the config keeping its other keys, as `keepfold init` now does too. `keepfold doctor` prints an `Excluded folders` line. The Chat tab's server is unaffected unless its working directory lies in a listed folder.
- **Kill switch.** `keepfold kill` writes `.keepfold/kill`; `keepfold kill --off` removes it (`share.killed(vault)` checks it). While it is on, `keepfold_as_me` returns `{error: "killed"}` in every role, and the reader role refuses every tool with `killed`; the owner's other tools work. `keepfold doctor` prints a `Kill switch` line (on or off).
- **Access log.** The server, never a tool call, writes one `log` event with `payload {kind: "access", access: "as_me", task (plain, ≤ 120), audience (plain, ≤ 80)}` per `keepfold_as_me` call (`Keepfold._access("as_me", task=…, audience=…)`). It goes into the open session, or session `cli` when none is open; `grader.client` is server-stamped. `keepfold_log(kind="access")` is refused (`invalid_argument`). `keepfold access [--days N]` (default 30) lists them oldest first: `day  HH:MM  client  as_me  audience  task` (an old vault's `draft` rows list too). Voids do not hide them.
- **Doctor.** `Vault outside cloud sync` WARNs when the vault path is under OneDrive, Dropbox, Google Drive or iCloud; `Vault git` WARNs on any remote, since a push would publish private pages.

### `keepfold export context` (CLI only)
`keepfold export context [PATH] [--vault V]` prints (or writes to `PATH`) a plain Markdown snapshot for other assistants: a header `# About me (Keepfold snapshot, YYYY-MM-DD)`, then `## Profile`, `## How to help me` (contract core rules), `## Current goals` (`## Now` of `me/goals.md`) and `## Preferences` (preference lines and prime's personality headings, `- [Section] text`, no labels). Only live act-grade claims (tier `typed` or `confirmed`, not `(ask)`, so no relayed yes from `claims.RELAYED_FROM`) are included; private me/ pages and lines matching a secret pattern are left out; links, URLs and HTML are stripped. At most 6,000 characters, trimmed by whole lines from the end. Stderr reports where it wrote and how many unconfirmed lines it left out. Refusals (`invalid_argument`, exit 1): run from an `exclude:` folder; `PATH` inside the vault, the Keepfold repo or an `exclude:` folder. `keepfold setup --print-mcp-config [--vault V]` prints only `{"mcpServers": {"keepfold": {"command": <keepfold>, "args": ["mcp", "--vault", <vault>]}}}` (the format Cursor and Gemini CLI read) and changes nothing (the hidden `export context --mcp-config` prints the same, after the `exclude:` refusal). Writes nothing in the vault.

### `keepfold concept duplicates` (CLI only)
`keepfold concept duplicates [--limit N] [--vault V]` (default 20) prints up to N candidate pairs of concepts that probably mean the same thing, best first: `k. SRC -> DST  score S`, both titles, an `evidence:` line and `run: keepfold concept merge SRC DST`. Read-only: it merges, writes and downloads nothing.

### `keepfold claims --summary` (CLI only)
`keepfold claims --summary [--vault V]` (`keepfold know` is a hidden alias) prints, per claim page (`me/preferences`, `personality`, `goals`, `profile`, `voice`), the live claim count, `tiers:` counts (`tiers:` ends with `(confirmed: N clicked, R reflected, M relayed)` when any line is confirmed; idea 11); then the same for all pages. A private page prints `me/<page>: private` only. Read-only: writes no event or file.

### `keepfold agent-text` (CLI only)
`keepfold agent-text [--vault V]` (RR-36) prints every fixed string an agent can see, each as `== <source> [<channel>] (N chars) ==` and its text: the server `INSTRUCTIONS`, each tool description, the `next` hint constants of `mcp_server` (`*_NEXT`, `OFFER`, `MOCK_BRIEF`, `ASK_FOCUS`; a dict one as `key: text` lines), `skills/keepfold/SKILL.md` (a checkout only), the prime hook's templates (`HEAD`, `NEXT`, `TAGGED`, `NUDGE`) and the rule-file block without a vault. Then `== chars per app profile ==`: per profile match (the vault's `.keepfold/profiles.json`, else the defaults) and `unknown`, the summed size of the channels that reach that app: `mcp` for every app, `plugin` (skill and hooks) for Claude, `rules` for Cursor, VS Code, Copilot and Codex. Vault text (claims, pages, the rule block's core lines) is never printed. Read-only.

### `keepfold forget` (CLI only)
`keepfold forget <what> [--vault V]` (R10, `keepfold.forget`) asks to confirm, then forgets a page (`people/<slug>`, a page id or `<folder>/<id>`, a chat page; not a concept, area or domain, which live in `catalog.yaml`, nor a browse page) or one claim line (`me/<page>^c-xxxxx`, any section, with the `## Past` lines that led to it) in every store Keepfold owns: the file or line through the vault; each event that holds its text (the page's id and title, the line's text) rewritten in place, keeping `id`, `ts`, `day`, `session`, `kind`, `mode`, `source`, `schema`, `predicted_p`, `grader` and, at any depth, the fold's ids (`ref`, `object`, `also`, `problem`, `mistakes`, `targets_mistakes`, `concept`, `assessment`, `claim`, a payload's `kind`), so levels, voids and `keepfold undo` fold as before (undo deletes a session's own event file even after a forget rewrote it); in every other string each copy becomes `[forgotten]`, a dict key holding it goes, and a line's text hash (`review.text_hash`, `line_hash`) goes; Keepfold's own pages (`sessions/`, `rollups/`, `log.md`, `Today.md`, `index.md`, `inbox.md` lines, chat pages), the `.keepfold/**.json(l)` caches (not `backups/` or `tmp/`), the chat transcripts under `chats.export_root()` (a forgotten chat page's own transcript deleted, its `chat-import.sqlite` record marked so it is never imported again), the index snapshot written again, vectors pruned (`semantic.prune`), damaged store copies moved aside by `keepfold.quarantine` deleted, and `vectors.db` and `chat-import.sqlite` compacted (`secure_delete`, `wal_checkpoint(TRUNCATE)`, `VACUUM`); then the AI apps' rules files with a Keepfold block are rewritten (`app.targets.refresh_rules`, so a `me/core` line leaves them) and the `.bak` that rewrite made is deleted. A page id is replaced only where a string equals it or in its link forms (`[[id]]`, `[[id|…]]`, `<folder>/<id>`, `<kind> <id>`), never as a substring; a title, line or //forget text only when specific (12+ characters, or 4+ in two words or more; from chats 12+), a person's title everywhere from 4 (the receipt's `notes` say every mention went); the `.keepfold` caches are swept but `watch-files.json` (a dropped path would re-import the file). Each file is checked outside the vault lock and replaced under it, one at a time. It then prints a receipt: `forgot <what>: removed …` (counts per store), the `notes` (a person's name redacted everywhere), a `rewritten: <file>` line per rules file, and `Keepfold cannot remove:` lines naming the vault's git history (with a `git filter-repo` command it never runs), backup zips, `raw/` and the export files, watched folders and Zotero (a changed file comes in again), AI apps' own copies, Claude Code's transcripts, a synced vault folder, rules files or older `.bak` backups beside them that still hold the text, texts too short or common to sweep, and the owner's own pages that still mention it. `keepfold browse forget` runs `browse.forget.purge`, the same finish (with the browse databases compacted too) and prints the same `Cannot remove` lines. Writes no event about the forget (a //forget's queue: //tags above).

## Resources (read-only, attached by hand)
R32b: an app that supports MCP resources lets the person attach these to a chat from its + or @ menu. Static resources (`mcp_server.RESOURCES`, `text/plain`), not a URI template, since apps list `resources/list` in their attach menu.
- `keepfold://core` (**Keepfold: Core**): the pinned core lines, as `keepfold_prime`'s Core block serves them (`packs.lines` with scope `core`): `## Core` and the lines in `<untrusted_note id="me/core">`.
- `keepfold://pack/<name>` (**Keepfold: Interview pack**, …) for each of `general`, `coding`, `writing`, `interview`, `research`, `review`: the context pack at 1,500 characters (`packs.sized`), in `<untrusted_note id="pack/<name>">`; `keepfold://pack/<name>/5000` (**Keepfold: Interview pack (5,000 characters)**) the 5,000 one. With nothing recorded a read says so in one line.
- **Limits, from the tools' code.** `_resource_uris` lists the core unless `Keepfold._withheld()` holds `me/core` (private, outside the app's profile scopes, or a reader's page not shared with work), and a pack only when the app's profile scopes (`profiles.scopes_for`) hold all of the pack's (`packs.PACKS`; `general` needs every scope). A pack beyond the profile is not listed and a read of it fails (`not shared with this app`); it is never served cut. So an app no profile names gets `keepfold://core` only (as `CORE_ONLY_NEXT`), a coding app the core and the coding pack. Packs are built with the same `_withheld()` pages left out (private me/ pages, a reader's unshared ones) and never hold a hidden subject's line. An excluded folder's server lists none; a reader with the kill switch on refuses a read (`_gate`, as for `keepfold_context`); `keepfold mcp --private` lists what the owner's server lists.
- **X-ray.** Every read writes an X-ray row: tool `resource:<uri>`, the client, the `^c-…` ids of the core and preference lines served, the characters. Listing writes nothing, and a read is not a `pack_copied` event (an attach is one chat's read, not text pasted into an app's standing instructions, so Connect's "Changed since your last copy" counts only the app's Copy).

**Rules**
- All sources count at full weight; `source` is for history only.
- Readers skip a torn final line and repair it on the next append.
