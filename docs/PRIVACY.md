# Privacy

## Local first

Your vault is plain Markdown and JSONL in a folder you choose. Keepfold needs no account and sends no telemetry. Settings live in `~/.keepfold/` on your computer.

## When Keepfold uses the network

**Downloads.** Only these reach the internet. Each one but the update check happens because you asked for it:

- **The search model** (about 150 MB, from Hugging Face, huggingface.co), once, into `~/.keepfold/models`. Keepfold downloads it only when you ask: `keepfold setup` runs it after you say yes, and the app runs it when you click **Download search model**. You can also run `keepfold model download` yourself. Nothing else downloads it; searches never do.
- **The update check.** While the app runs, it asks GitHub (api.github.com) for the latest Keepfold release a minute after it starts and every 6 hours, and when you click **Check for updates** (Status → Updates). The request carries nothing about you, not even your Keepfold version. If GitHub's API is limiting requests from your network, it reads the latest release from github.com's release page instead. When a newer release exists, a Keepfold installed with `KeepfoldSetup.exe` downloads the new installer and its checksum from that release in the background; nothing is installed until you click **Restart to update**. To check only when you click, turn off **Check for updates automatically** under **Status → Updates**.
- **In the app, only when you click** (Setup, Local model and Status):
  - Ollama itself (about 1 GB): `winget install Ollama.Ollama` on Windows (from ollama.com) or `brew install ollama` on macOS (from Homebrew). On Linux the app only shows the install command.
  - A local model: `ollama pull` (from Ollama's library) or `lms get` (LM Studio's catalogue), about 2 to 6 GB depending on the model you pick.
  - In Connect AI apps, adding the Claude Code plugin runs `claude plugin marketplace add` and `claude plugin install` on your Keepfold folder (or, when Keepfold has no source folder, on its GitHub repository, which Claude Code then downloads).
- **Installing and upgrading** (uv, git and the Python packages) download from their usual sources.

**Servers on this computer only.** These listen on 127.0.0.1 (loopback), so no other computer can reach them:

- `keepfold app`: the app page. Every request needs a key that changes each launch. The browser app stops after 30 minutes idle; the tray app runs until you click Quit.
- `keepfold browse serve`, the receiver, opens no port since 0.3.2: it only imports new history from your browsers in the background.
- The MCP server (`keepfold mcp`) talks to Claude through standard input and output, not the network.

**Local model calls.** When you turn on a local model, Keepfold talks to Ollama (127.0.0.1:11434) or LM Studio on this computer only. It refuses any address that is not loopback, sends `localhost` to 127.0.0.1, ignores proxy settings, and refuses models whose name marks them as cloud models (Ollama's `-cloud`).

**Facts from your chats.** Keepfold saves facts you stated about yourself in your recent chats using your local model only. The model reads only your own messages of non-private chats, and nothing leaves this computer.

Searches, topic filing (`keepfold topics`), the dashboard, the Claude Code hooks and every tool run offline.

`keepfold doctor --security`, the security self-test, runs offline on a made-up vault in a temporary folder that it deletes afterwards; it never reads your vault, your notes or your settings.

## Where Keepfold connects: the registry

Every place in Keepfold's code that can reach the network is listed in one registry, `src/keepfold/egress.py`. `keepfold doctor --privacy` prints its lines, and the app shows them under Status, **Where Keepfold connects**:

- **github.com**: the newest Keepfold version and, when there is a newer one, the installer and its checksum. A minute after the app starts, every 6 hours while it runs, and when you click Check for updates or Update now.
- **ollama.com, git-scm.com and LM Studio's catalogue**: a model's size, and the downloads of Ollama, Git or a local model. Only when you click Install, Download or Get.
- **pypi.org and huggingface.co**: the voice-memo speech model and its package. Only from `keepfold model download --voice` or its Download button.
- **huggingface.co**: the search model and the reranker. Only from `keepfold model download` or Download search model, with Hugging Face's telemetry turned off (`HF_HUB_DISABLE_TELEMETRY`).
- **Your cloud model's address**: titles of browsed pages in categories you set to cloud, with your API key. Only when you turn on cloud processing.
- **github.com through Claude Code**: Claude Code downloads the Keepfold plugin. Only when you connect Claude Code or say yes in `keepfold setup`.
- **The AI apps you connect** (Claude, Cursor, Codex, Gemini CLI and the others): what Keepfold hands them, which they send to their own AI provider. Your pinned lines also go into their rules files and into the Keepfold tool description they read. Change it under Connect AI apps → Agent profiles, stop it per folder with `keepfold exclude add`, or remove an app under Connect.
- **pypi.org, files.pythonhosted.org and github.com, through uv**: Python and Keepfold's packages, when you install Keepfold or apply an update.

Local model calls and the app's own page stay on 127.0.0.1. Windows' text recognition for scanned PDFs runs on this computer and makes no connection. A test (`tests/test_egress.py`) scans the code and fails when a module that can reach the network has no entry in the registry, and another (`tests/test_egress_runtime.py`) runs indexing, prime, recall, Chat, Review, an import and the dashboard with every outside connection blocked.

## What the AI model sees

Keepfold is a tool that Claude (or another MCP client) calls. **Whatever a tool returns goes to the AI model you are chatting with**, which is Anthropic when you use Claude.

Every new chat starts with a short Keepfold context (`keepfold_prime`): your profile summary, the preference and personality lines that match your first message, the core of your teaching contract, and the titles and summaries of related pages. In Claude Code the plugin's hook adds it to the first message of **every** chat, in every project, before Claude answers. In Chat, Claude calls `keepfold_prime` itself. In Claude Code, Keepfold does not store your message; it notes only the chat's id in the vault so it adds the context once. In the Claude desktop app's Chat tab, which keeps no file Keepfold can read, Keepfold saves your messages to `~/.keepfold/claude-chat/claude-live/` so the chat can become a page (see [Past chats](#past-chats)). The words of each search an AI app makes through Keepfold are kept in `.keepfold/recall-log.jsonl` (the last 5,000). To stop this in Claude Code, turn the plugin off with `/plugin disable keepfold@keepfold`, or stop it for one folder and everything under it with `keepfold exclude add <folder>`: chats there get no context, and the Keepfold server there refuses every tool, reads included, and tells Claude only that Keepfold is turned off in that folder.

Keepfold limits what it hands over:

- Pages marked `private: true` are left out of search, recall and context. People pages (`people/`) are private unless you mark one `private: false`. Apart from the people-page exception below, only your local model reads private pages, in the app's Chat and `keepfold ask` (see below).
- Private is a rule Keepfold's tools follow, not a lock on the files. Your vault is plain files: any program that runs as you can read them, including an AI coding agent with file access (Claude Code, Codex, Cursor) if it is asked to, or tricked into it, by text it reads. `keepfold exclude add` stops Keepfold's own tools in a folder; it does not stop an agent from opening files. Keep anything no AI app may ever see out of the vault, or outside the folders your coding agents work in.
- Every Keepfold tool Claude calls goes through one access gate: a private subject (a private domain, area or concept and everything under it) and its mistakes do not exist for Claude. Studying one by its id (`keepfold_ask`, `keepfold_grade`, `keepfold_log` self-reports) gets the same answer as an id Keepfold has never heard of, so Claude cannot even learn that it exists, and no list, card or open-mistake line names one. Study private subjects in the app's Chat or at your own terminal.
- The app's X-ray **dry run** shows what an AI app's first call would get for a message you type, without calling the app: nothing goes to it or to any model, and nothing is written or logged, your message included. It shows only titles and the lines about you that X-ray already lists, never page text, and a private page only as "a private page".
- X-ray now also keeps the ids of the pages an AI app got from `keepfold_find`, `keepfold_recall` and `keepfold_read` (ids only, never your query or page text). A reply you paste into X-ray's **Trace** is matched on your PC with no model and is never kept: not in a file, a log, an X-ray row or an event.
- A session's page (`sessions/`, which the app's home and Export snapshot show) never names a private subject or a private page changed in it: they are left out with one line such as "1 private topic not listed." Your results are still recorded in full.
- **One exception: people pages.** When Claude asks for a people page by its exact id (`keepfold_read`), Keepfold returns it even if it is private, with a note asking the model to use it for the current task only. That note is a request, not a lock: the page's text goes to the AI app you are chatting with. If a chat has already read outside text (a web page or an imported chat), Keepfold refuses a private people page there, so text from outside cannot steer it into a message. If a person's page holds something no cloud AI should read, keep it out of the vault.
- Share tiers decide which of your `me/` pages may be shown for a given audience when Claude writes as you (`keepfold_as_me`). Lines from other pages are held back by Keepfold itself; the model only learns how many. A read-only (`reader`) Keepfold serves only `me/` pages marked `share: work` or `public`, in every tool, never reads past chats (`keepfold_chats`) or people pages, and writes nothing when it starts.
- The kill switch (`keepfold kill`, undo with `keepfold kill --off`) stops writing as you (`keepfold_as_me`) and the read-only role at once.
- `keepfold export context` writes a short snapshot (profile, contract rules, current goals, confirmed preferences) only when you run it. Whatever you paste from it into another assistant goes to that assistant's company.

## Prompt injection

Notes can contain text from the web or other people. Keepfold treats note text as data:

- Over MCP it wraps note text in `<untrusted_note>` tags, so the model can tell your notes from instructions.
- In Claude Code, a hook marks the session after Claude reads the web or another tool, and later changes to your `me/` pages are recorded as "exposed" or refused.
- Every write to your pages, events and generated files is scanned for secrets (keys, tokens, passwords) and refused if one is found. The working files in `.keepfold/` (below) are copies that never enter git and are not scanned again.
- Lines on your `me/` pages go word for word into other AI apps' rules files, so Keepfold refuses to save one that reads like an instruction to an AI or holds invisible characters, and a line already there (typed in Obsidian) is given to no AI app until you click **Keep it** in Review.
- The same pinned core lines those rules files carry are also added to the `keepfold_prime` tool's description, which every AI app connected to Keepfold reads (Claude Code excepted); private pages and unconfirmed lines never go there.
- The dashboard runs with a strict content security policy and no network access.

These measures lower the risk; they do not remove it. Review changes to your `me/` pages now and then: every session is a git commit, and `keepfold undo` reverts one.

## Your data

- The vault has its own git history, so every change can be reviewed and undone. You can turn it off on the app's Vault page (see Browsing below).
- A file you attach in the app's Chat is read into the app's memory only (its uploaded copy in `~/.keepfold/tmp` is deleted as soon as it is read), goes only to your local model, and is saved to the vault only when you click **Save to your brain**; the saved chat names the file and page, never its text.
- A pre-push hook in the vault stops an ordinary `git push` (it is a guard against mistakes; `git push --no-verify` skips it). If your vault already had a pre-push hook, Keepfold keeps yours. **Do not publish your vault**, for example to a public GitHub repository: it holds your profile, private pages and voice samples.
- The vault's `.keepfold/` folder holds working files: the search vectors (`vectors.db`: numbers made from your non-private pages and the place of each page, no text; an older `vectors-v3.npz` is read into it once and never written again; the first forget that touches a page in it deletes it), a log of Claude's recent Keepfold searches (the last 5,000), `index-snapshot.json`, and a copy of the parsed text of your pages that makes start-up faster. Keepfold no longer writes `dashboard.html` there: an old one is moved to `.keepfold/backups/` once. Export snapshot (in the app) saves one page of your non-private pages (up to 20 KB of text per page) only where you choose. If you import browsing it also holds `browse/store.db` (Keepfold's own browsing store: every visit that passed the filter, with its address, title, search term and time, kept after the browser forgets it; the local model's judgements; the site pages, once they moved out of the vault's Markdown files; the visit counts per day and site, with each counted page's address and title, kept after the browser forgets them; and the privacy filter's verdict on each kept visit (its cleaned address, title and category, under a hash of the original address and title), so a visit read again is not judged again (never for a visit that was not kept; emptied when the filter or its word lists change); a forget overwrites what it deletes), `browse/vectors-private.db` (search vectors of your **private** browsing pages, for local models only, kept apart from the vectors above; an older `browse/vectors-private.npz` is read into it once and kept as a backup), `browse/sites.json` (the local or cloud model's sorting and summaries of each site), `browse/site-days.json` (the visit counts from before they moved into the store, read in once and kept as a backup; a forget filters it too), `browse/verdicts.json` (older judgements of the local model; new ones go into the store, by a hash of the text, never the text), `browse/inbox-archive/` (the visits the old browser extension saved, after the filter, kept so a rebuild does not lose them; Keepfold 0.3.2 removed the extension, so no new ones arrive; no page text for private visits; older than both your browsers' history and 90 days is removed) and `cloud-log.jsonl` (one counts-only line per cloud processing run). When the site pages move into the store, the old Markdown site pages are first zipped into `.keepfold/backups/browse-pages-<date>.zip`, private ones included; that zip stays until you delete it. They stay on your computer and are left out of the vault's git history; `keepfold backup` includes them. You can delete them at any time; Keepfold rebuilds what it needs, except the extension's archived visits, which only the extension had. If `vectors.db`, `browse/vectors-private.db` or `chat-import.sqlite` is found damaged (a sync tool can copy a database apart from its `-wal` file), Keepfold never deletes it: it renames it `<name>.damaged-<date and time>` (with its `-wal` and `-shm` files), starts a fresh one and `keepfold doctor` names the copy until you delete it. A forget deletes these copies, and `keepfold backup` leaves them out.
- Keep the vault out of OneDrive, Dropbox, Google Drive and iCloud folders. Sync can break Keepfold's file lock and copies private pages to the cloud. `keepfold doctor` warns about this.
- Export: `keepfold backup` writes a zip of the whole vault, including its history, `browse/private/` and the browse stores in `.keepfold/browse/` listed above (a snapshot of `store.db` and `vectors-private.db`, `sites.json`, `state.json`, `inbox-archive/`, the extension visits not yet imported, and the older `site-days.json`, `verdicts.json` and `vectors-private.npz` as `*.migrated` backups: the app's start or the next browse import reads each into its store once and renames it, never deletes it, and a forget still removes what it forgets from them; `keepfold doctor` names any not read in yet), which hold browsing your browsers have already forgotten, and a snapshot of `.keepfold/vectors.db`. It leaves out the old browser extension's pairing token, your local chat history (`.keepfold/browse/chat/`), lock files, older backups and an old `dashboard.html`. **A backup zip holds your private browsing: keep it as private as the vault itself.** `keepfold backup --no-private` writes a zip without private pages, pages under a private subject, the raw files of private resources, `browse/private/`, the browse stores in `.keepfold/browse/` (their visits mix private browsing in), the chat import's state (`.keepfold/chat-import.sqlite`, which holds the raw turns of private chats too) and the history (`.git`, which holds every private page); your event log, with your results on private subjects, stays in it.
- `~/.keepfold/logs/` holds the app's status lines and error types (never note text) and the address of the running app, without its key. `~/.keepfold/app.json` holds the key while the app runs; programs running as you can read it.
- Before 0.6.2 the settings folder was `~/.cortex`. Keepfold moves it to `~/.keepfold` the first time it runs (moved, not copied), so only `~/.keepfold` is left. [INSTALL.md](INSTALL.md#coming-from-cortex) has the details.
- Delete everything: delete the vault folder and `~/.keepfold` (settings, models, logs, chat copies and any downloaded update). In each AI app you connected, remove Keepfold first (Connect AI apps → Remove, or uninstall with the default "remove from AI apps"), then delete the `*.keepfold-*.bak` files Keepfold left beside their config and rules files: they hold copies of your pinned lines. The installer's log is `%TEMP%\keepfold-setup.log`. See [INSTALL.md](INSTALL.md), section 11.

## Forgetting one thing

`keepfold forget <page or line>` (a page such as `people/asha` or a note's id, a saved chat page, or one line about you such as `me/profile^c-ab2cd`), a `//forget:` line that matches one line about you, and the //forget card in the app's Review all forget the same way. A `//forget:` line retires the line at once, so AI apps stop getting it; the Keepfold app removes it from everywhere else within 10 minutes, or when it next runs. `keepfold browse forget --site` and `--category` do the same for browsing.

**What it removes.** The page or line itself (a line together with the `## Past` lines that led to it; a person together with the voice samples and drafts addressed to them). Then every copy of its text Keepfold keeps: the page's id and title, or the line's words, in the event log (each event that held them is rewritten with `[forgotten]` in their place), in Keepfold's own pages (session notes, summaries, `log.md`, `Today.md`, `index.md`, `inbox.md`, saved chat pages), in the working files under `.keepfold/` (the search log, the X-ray, the local Chat's history and the other ledgers), and in the chat copies Keepfold keeps under `~/.keepfold/claude-chat` (a forgotten chat page's own copy is deleted, and that chat is never imported again). The rules files Keepfold writes your pinned core into for other AI apps (Cursor, VS Code, Codex's `AGENTS.md`) are rewritten at once, and the receipt names each. The search snapshot is written again, the page's search vectors are deleted, and the databases are rebuilt (`VACUUM`, after emptying their write-ahead log) so no deleted row stays in free space. The event log keeps each rewritten event's id, time, day, kind and the ids of what it graded, so your levels and `keepfold undo` work as before. Keepfold writes no record of what you forgot, except that a `//forget:` leaves two events naming the line's id and counts (its words in them swept), so the app knows the sweep ran.

**What it cannot remove**, and says so in the receipt it prints:
- The vault's git history: every old version of the page stays there. Keepfold never rewrites history; the receipt shows the `git filter-repo` command you can run yourself, after which any clone or remote copy must be deleted too.
- Backups: the zips in `.keepfold/backups/` and any made with `keepfold backup --to`.
- Raw exports under `raw/` and the export files you imported, wherever you saved them.
- What AI apps already received: their own chat histories, memories and Claude Code's transcripts in `~/.claude/projects`. For a line of your pinned core, the older `.keepfold-*.bak` backups beside those rules files keep it until you delete them; the receipt lists them.
- A synced vault folder's version history (OneDrive, Dropbox and the like).
- Copies in other words: Keepfold removes the exact text (any case and spacing), not a paraphrase. It sweeps a title, a line or a `//forget:`'s words only when they are specific (12 characters or more, or 4 or more in two words or more; from chats, 12 or more), so forgetting a page called "Python" leaves every other "Python" in your chats alone; the receipt lists what it did not sweep. A page's id is removed only where it stands alone or as a link (`[[id]]`, `folder/id`), never inside other words. A person's name is the exception: it is swept everywhere from 4 characters, one word too, so every mention of anyone with that name goes, and the receipt says so.
- Watched folders and Zotero keep their files. Keepfold remembers each watched file's path, so an unchanged file is not read again; a file that changes comes in again, so delete it there or stop watching its folder.
- Your own pages that still mention it: Keepfold leaves what you wrote and lists those pages.

A forget cannot be undone.

## Browsing

Keepfold can turn your browser history into pages. It is off until you run an import, and [GUIDE.md section 6](GUIDE.md#6-your-browsing) explains every step and setting.

**After your first import, new history comes in by itself.** While the app runs, Keepfold reads the visits that are new since the last read every 10 minutes (the receiver alone: every `browse.auto_import_hours`, default 6; 0 turns both off). The local model checks new titles only while the computer is idle and the model is already loaded; Keepfold never loads it for this. It reads only the browsers and profiles you imported before; a profile you untick in the app is remembered and left out of every import until you tick it again. Nothing is read before your first import.

**Who may see each category.** Every browsing category (news, video, health, money and so on) has one of three settings:

- **Skip** (Don't save in the app): never saved at all. Adult is skipped by default. A site the local model files under a skipped category after it was stored is dropped the same way, so Chat never lists it.
- **Local models only:** saved on private pages in `browse/private/`. Only a local model on this computer (Ollama or LM Studio) may read them. They never appear in search, the dashboard or any cloud chat. Every sensitive category (health, money, betting, dating, sexuality, drugs and self-harm) starts here.
- **Cloud AI apps can read:** saved on normal pages that Claude, Gemini, ChatGPT, Cursor and other AI apps can read through Keepfold. Nothing is in this group until you turn on `browse.visible_to_claude`. For these categories the site pages include the **page titles, the search terms and the site names**, so those apps can read them, not only your topics and time. The setting is stored as an allowlist, `browse.cloud_categories`: a category Keepfold adds later starts as local-only until you choose otherwise. (Older configs that list `hidden_from_claude` keep working, and categories they did not know are local.)

**When unsure, it stays local.** A page title or search term on a site page Claude can read must first pass two checks: the built-in sensitive word lists (health, money, sexuality, drugs, self-harm and the rest), and, when a local model is set up, that model's judgement, made on this computer before the page is written. **Search terms reach a readable page only after the local model has called them ordinary**; without a local model they stay on the private pages. A title the word lists cannot place and no local model has judged stays private too. The local model's judgements are kept in `.keepfold/browse/store.db` by hash; a cloud model is never asked.

**Changing your mind removes the past too.** When you skip or hide a category, or add a site to `deny_domains` or `private_domains`, the next import takes what the new settings no longer allow out of everything already stored: the day and site pages (private ones included), the visit counts, the search vectors, the site summaries and the extension's archive. To remove one site or category at once, run `keepfold browse forget --site <domain>` or `keepfold browse forget --category <name>`; it prints what it removed. Add the site to `deny_domains` too, or the next import reads it again from your browser.

**Private pages stay out of git.** The vault's `.gitignore` lists `browse/private/`. A vault made before this release may have committed them: the next browse import stops tracking them (once, keeping the files), and `keepfold doctor` warns if older commits still hold them, with the commands to rewrite that history. Keepfold never rewrites history itself.

**Your choice: git on or off, private pages in or out.** Two settings on the app's Vault page (`git:` in `~/.keepfold/config.yaml`) decide this. *Keep the vault's history in git* is on by default; off, Keepfold makes no commits at all, so nothing new enters the history, `keepfold undo` is off, and an existing `.git` folder is left untouched (delete it yourself if you want the old history gone; until then `keepfold doctor` still warns if it has a remote or private pages in old commits). *Include private browsing pages in git history* is off by default, which is what this section describes. On, Keepfold removes its own `browse/private/` line from `.gitignore` and your private pages are committed like any other page: the history then holds every version of them, and `keepfold browse forget` removes what it forgets from the files on disk but not from old commits (it never rewrites history, for any page). Both histories use more disk space as the vault grows; that is the trade-off for being able to undo.

**Your websites in the app's brain.** The app's home draws your sites as the brain's stem, with a side panel per site (visit days, searches, page titles). Only the app's own page reads them, from the browsing store on this computer, with its per-launch key; the MCP server, Claude, other AI apps and cloud models never get them through it. While the lock is closed it reads only the sites Claude may read: private and local-only sites are not drawn, not counted, not linked, and asking for one answers "not found". They appear only while the lock is open (Windows Hello) and leave on the next refresh after it locks. Export snapshot has no stem. Where each site sits in the stem is kept in memory only, never in a file.

**Processing.** Sorting sites into categories and writing their one-line summaries uses your local model, unless you turn on cloud processing (below) for the "Cloud AI apps can read" categories. Sign-in, payment and bank pages that Keepfold's built-in lists recognise are dropped and never stored. Add any other site to `deny_domains`.

**Also built in this release:**

- **Cloud processing**, which lets a cloud model sort and summarise the "Cloud AI apps can read" categories. It is opt-in and off by default, for everyone. It never sees a skipped or local-only category, and if no local model is available, local-only data is skipped, never sent to the cloud.
- **A local chat** (Chat in the app, and `keepfold ask`) that answers questions about your archive, private notes and private browsing included, with your local model only. Private notes are searched apart from the search Claude uses, and their search vectors are kept in memory only, never written to disk. It never uses the cloud model, whatever the cloud settings say. Chat history stays on this computer, in `<vault>/.keepfold/browse/chat/` inside the private browse folder: it is never served to Claude or any other AI app, never on the dashboard and never logged. Delete it in Chat settings, or turn Keep chat history off to write nothing. Questions about your sites, your studying and your days are answered from Keepfold's own records with no model at all. The Private notes and browsing switch in Chat settings (on by default) decides whether Chat reads private notes, private subjects, private mistakes and private browsing, in its search and in these answers alike. `keepfold ask` prints its answer in the terminal, so it reads private notes and private browsing only when you add `--private`. Run that yourself: an AI coding tool such as Claude Code that runs a command reads its output. `keepfold ask --private` refuses to run unless both its input and its output are a real terminal window, so an AI app that runs it (through a pipe) gets a refusal, not your private notes.
- In the app, the cloud settings never take an API key: you name the environment variable that holds it, and the page shows only whether that variable is set.

**Two things to know:**

- Keepfold 0.3.2 removed the browser extension. If it is still installed, remove it from your browser's extensions page: it keeps a queue of visits in the browser's own extension storage (a visit older than 24 hours is dropped), and nothing takes them any more.
- `keepfold backup` includes `browse/private/` and the browse stores in `.keepfold/browse/` (visit counts, site summaries, verdicts, the old extension's archived visits, the private search vectors); it leaves out chat history ([Your data](#your-data)). Keep backup zips as private as the vault itself, or make one with `--no-private`, which leaves out private pages, `browse/private/`, the browse stores, the chat import's state and the history.

## Past chats

`keepfold_chats` and `keepfold chats` read your Claude Code transcripts in `~/.claude/projects` on this computer (the desktop app's Code tab writes them too), Cowork task transcripts in the desktop app's own folder (`%LOCALAPPDATA%\Claude-Data\…\local-agent-mode-sessions` on Windows), and the Chat-tab log described below. ChatGPT, Gemini and Perplexity conversations, and claude.ai chats from before the log, are read only after you import an export yourself with `keepfold import` (or `keepfold import-chats`). Secrets in transcripts are replaced with `[redacted]` before Claude sees them. Reading a chat saves nothing; what Claude learns about you from it waits as unconfirmed until you agree.

**The Chat-tab log.** The desktop Chat tab keeps no file Keepfold can read, so every Chat-tab chat is logged through Keepfold's own tools. When a Claude app with no transcript Keepfold reads (the Chat tab) calls `keepfold_prime`, Keepfold appends your message to `~/.keepfold/claude-chat/claude-live/<chat id>.jsonl`, outside the vault. At each later turn the chat sends your new message, verbatim, and a one-line gist of its previous answer (at most 300 characters). Each line holds only the role, the text and a time Keepfold stamps itself. Secrets are replaced with `[redacted]` before anything is written. Nothing is logged for Claude Code (its transcripts already exist), for any other app, or when the server runs for someone else (a delegate or reader role). The file stays on this computer. It becomes a chat page through the automatic save below, with your messages only, never the gists. To stop it, remove Keepfold from Claude Desktop under Connect in the app; to delete a log, delete its file.

While the app runs, it also saves those chats as chat pages in your vault every 5 minutes (on by default; turn it off on the Status page under **Past AI chats**). This runs on your computer with no AI model. A page holds only your own messages, never the AI's replies. A coding session holds only a summary: the files touched, as paths inside the project, and the commit messages, never code, diffs, command output or file contents. Secrets are redacted. Each page follows its category's setting under browsing privacy. A category set to skip is never saved. A category kept on this computer makes the page private, so Claude cannot read it; the app's Browsing page lists those chats under **Chats kept private** with their title, app, date and the category that caused it (never their text, and only on the app's own page, not over MCP; while the Private lock is closed it shows only how many there are per category, and the titles appear after you unlock it with Windows Hello). Every other chat page is a normal page Claude can read. Sessions in a folder you excluded with `keepfold exclude add` are skipped. What the import has read so far is kept in `.keepfold/chat-import.sqlite` inside the vault, a git-ignored cache of your own messages. Deleting it only makes the next run read the chats again.

**Chat pages stay out of git.** Chat pages live in the vault's `archive/chats/` folder, which the vault's `.gitignore` lists, so they are in no new commit of the vault's git history and in nothing you push. They are still normal pages on your disk: search, recall, Chat, the brain map and links work as before, a private chat page stays private, and `keepfold backup` includes them. Chat pages saved before this release sat in `resources/`; the app moves them once, on its next chat save, and `keepfold chats archive` does the same by hand (`--dry-run` lists them first). If the vault is a git repo, Keepfold runs `git rm --cached` on their old paths and commits that, so git stops tracking them, but older commits still hold them: Keepfold never rewrites history. `keepfold chats archive --undo` moves them back to `resources/`, commits them there, and keeps new chat pages there until you run `keepfold chats archive` again. `keepfold doctor` warns if the `.gitignore` line is missing; `keepfold init` adds it.

## Imported notes, calendars, documents, projects and highlights

`keepfold import` turns a notes folder (Obsidian, Notion or any `.md`/`.txt` files), a calendar (`.ics`), a folder of documents, a folder of your git projects, reading highlights, your Zotero library or your Anki decks into pages in `resources/`, and so does a folder you watch. **Each import asks who may read them** (in a terminal window, and in the app before Import), once per source, and remembers your answer in the vault's `.keepfold/import-tiers.json`. `private` makes every imported page private. `skip` imports nothing. `normal`, the default, makes **normal pages that Claude and every other connected AI app can read**, unless the note's frontmatter marks it private. When nothing can be asked, the import uses your last answer or the default, and says which. **A stricter answer reaches the pages already imported:** changing a source to `private` makes every page an earlier import of it wrote private too (the pages that say `Source: <that source>` under their title), and says how many; changing it to `skip` deletes nothing but says how many of its pages are still in your vault and how to remove them. Changing to a looser answer never makes a private page normal again. `--tier` (or `--private`) sets it on the command line. A note counts as private when its frontmatter sets `private` to any yes value (`true`, `"true"`, `yes`, `on`, `1`), when it has a `private` tag, or when its frontmatter cannot be read. Every import ends with a report line: how many items it read, imported, made private, found already imported, and skipped, with the reason. Attendees' email addresses are left out of calendar pages, and secrets are redacted. `keepfold import --dry-run` shows the counts first and writes nothing.

What each of the newer imports reads, and what it never reads:

- **Documents** read the text of each `.pdf`, `.docx`, `.md` and `.txt` file in the folder you name, and keep a PDF's title and creation date and a Word file's title. A page keeps the document's whole text up to about 500,000 characters (about 250 pages) and says when it kept fewer pages. Other file types, hidden folders and encrypted files are never read, and neither are images in a document, except on a scanned PDF page with no text, which Windows text recognition (OCR) reads on this computer; nothing is sent anywhere.
- **Git projects** read, per project: the project's own `git config user.email`, `git log` for commits by that email (dates and the one-line commit messages only), the names of the files in the project's top folder (to name its languages) and the first part of its README. They never read code, diffs, commit bodies, other people's commits, other files' contents, or the contents of manifest files such as `package.json`. Code blocks in a README are left out.
- **Reading highlights** read the Kindle `My Clippings.txt`, Readwise or Pocket `.csv` you give: book or article titles, authors, your highlights and notes, and their dates. A Pocket list keeps the title, link, date and tags of each saved article. Nothing else on the Kindle is read.
- **Sent mail** reads the `.mbox` file you give: each message's headers (From, To, Cc, Date, Subject, Message-ID and Gmail's labels) and the text body of your own sent messages. It keeps the date, subject, the recipients' names and your own words. It never keeps an e-mail address (recipients become names, an address in your text becomes `[address]`), other people's messages, quoted replies, forwarded parts, signatures, drafts or attachments. It defaults to private.
- **Notes to self** read a WhatsApp chat export (`.txt`, or its `.zip`) and Telegram's `result.json`: the date, time, sender and text of each message, and whether it holds media. They keep your own messages only (a WhatsApp chat anyone else wrote in is skipped whole; in Telegram only Saved Messages, without forwarded messages), a line each, with media named as `[photo]` and the like. Photos, voice notes and other files are never read or copied, and other Telegram chats are never kept. It defaults to private.
- **Location** reads Google Timeline JSON (Takeout's Semantic Location History or the phone's `Timeline.json`): each place visit's start time and postal address. It keeps one city per day, nothing finer. Coordinates, street addresses, place names, movements and raw points are never kept (`Records.json` is not read at all), and nothing is sent anywhere to look a place up. It defaults to private.
- **Photo dates and albums** read, for each photo in the folder you name, its file name, folder name, modified date and two EXIF fields (DateTimeOriginal and DateTime). They keep, per day, the number of photos and the folder (album) names. The images themselves, thumbnails, GPS and every other EXIF field are never kept, and Google Photos' `.json` sidecar files (which hold places) are not read. The default is normal, like highlights: choose private if your album names say more than you want shared.
- **Spotify** reads the streaming history files in Spotify's export: per play, its time, how long it played, and the track, artist or podcast name. It keeps, per year, the total hours and the top artists, tracks and podcasts by time. It never keeps a single play, nor the IP address, country, device or other fields the extended history holds, and it does not read the export's other files (account, payments, search queries). The default is normal, like highlights.
- **Voice memos** read the audio files (.m4a, .mp3, .wav, .ogg, .opus, .aac) in the folder you name, and each file's name and modified date (for the day it was recorded). The speech is transcribed on this computer by faster-whisper, a local speech model; the audio never leaves the computer and is never copied into the vault. A page keeps the transcript of your words (silence and Whisper's invented filler left out), the day and the file's path. To spell your terms, the model is given up to 40 concept titles and your people pages' names, never a note's text. Pages are private by default. The speech model and faster-whisper are installed only when you click Install on the Voice memos card or run `keepfold model download --voice` (about 150 MB from huggingface.co and pypi.org); no import downloads anything.
- **Zotero** reads a copy of your library's database (`zotero.sqlite` and its `-wal` file), made in a temporary folder and deleted after, so Zotero's own files are never written or changed, and the PDF and Word files attached to your items (in Zotero's `storage` folder, or where a linked file sits). To find the library it reads two settings in your Zotero profile's `prefs.js` (whether a custom data folder is used, and where). It keeps, per item of your own library: its title, kind, publication, date, authors, DOI, URL, tags and abstract, your notes, your highlights and their comments, and the attached files' text. It never reads group libraries (other people's items), the trash, or Zotero's account and sync data, and nothing is sent anywhere, Zotero's servers included.
- **Anki** reads a read-only copy of your collection (from an `.apkg` or `.colpkg` export, or from your profile's `collection.anki2` and its `-wal` file), made in a temporary folder and deleted after, so nothing is ever written to Anki's files. It keeps, per deck: the deck's name, card counts, review counts, how much you recalled, the day of your last review, and the front of up to 10 leech cards as one line of plain text (links, images and sounds left out). It never keeps your other cards, your review history line by line, or Anki's media and sync data, and nothing is sent anywhere.
- **Watched folders** (`keepfold watch add`, or **Watched folders** in the app) read only what the import of their kind reads (above), in the folders you add, every 10 minutes while the app runs. Between passes the vault keeps the watched folders in `.keepfold/watched.json` and each file's path, modified time and size (a Zotero item's fingerprint) in `.keepfold/watch-files.json`, never their contents. A watch never follows a link out of its folder and never reads hidden or system files, files kept only online (reading one would download it), or the vault itself. Nothing is sent anywhere.

## What Keepfold never captures

Each line says where it holds.

- **Secrets, keys and passwords**, from every source. They become `[redacted]` before anything is written. A write that still holds one is refused.
- **Text you wrap in `<private>…</private>`** in a chat. It becomes `[private]` before anything is written (chat logs, chat pages, imported chats, Keepfold's Chat, the recall log, saved pages and lines); the AI app you typed it to still sees it.
- **Sign-in, payment and bank pages** that Keepfold's built-in lists recognise. Browsing visits to them are dropped and never stored. Add any other site to `deny_domains`.
- **Adult browsing.** It is skipped by default. You can choose to keep it on private pages instead.
- **AI replies in your vault's chat pages.** A saved chat page keeps only your own messages. The copy of an imported export in `~/.keepfold/claude-chat`, which `keepfold_chats` reads, keeps the whole conversation.
- **Code, diffs and command output from AI chats, coding sessions and git projects.** A coding session keeps only the files touched and the commit messages. A git project keeps its README's start (code blocks left out), its languages from file names and your commit messages. Your own notes and documents keep the code you wrote in them.
- **The content of images and audio.** Keepfold imports text only. At most a date and a coarse place are kept from a photo or recording, never what it shows or says.
- **Other people's quoted text in mail**, from mail imports. The quoted lines after "On … wrote:" are dropped, and so is everything from an "Original Message" or "Forwarded message" line on. Your own notes and calendar keep what you quoted in them.
- **Location finer than a city**, from location and photo imports. Their coordinates are rounded to about 10 km. Your own notes and calendar keep the places you wrote in them, and browsing keeps the addresses you visit as they are, map links included.
- **Labels about your health, sexuality, religion or politics.** Keepfold never guesses them. Browsing categories with those names exist only to keep those visits on this computer.
